# VIP / SVIP 会员与知识咨询

本模块接入现有 Qt 客户端、TCP 服务端与 SQLite，保持 `feature/apple-ui` 的现代界面。所有购买、充值和扣费均为教学模拟，不连接真实支付或真实设备。

## 使用入口

- 用户端 → 个人中心 → **会员中心**：套餐对比、购买/同级续购、有效期、续费授权与取消。
- 用户端 → 个人中心 → **AI 咨询**：仅有效 SVIP 可提问，答案下展示检索到的已发布知识来源及版本。
- 管理端侧栏 → **会员套餐**：编辑 12 种组合的价格、折扣与上下架状态。
- 管理端侧栏 → **咨询知识库**：保存草稿、审核发布、停用；保存草稿不会替换线上版本。
- 充电预约、实时计费、结算与个人订单列表：使用本单锁定的会员优惠，结算显示原价、优惠、实付。

### 教学默认套餐

以下金额只是可修改的演示初始值，不是需求矩阵指定价格，也不构成真实销售方案。每种类型均提供 1、3、12 个自然月，价格为下表月价乘以月数，共 12 个组合。

| 等级 | 固定期限月价 | 连续订阅月价 | 充电折扣 | AI 咨询 |
| --- | ---: | ---: | ---: | --- |
| VIP | ¥15 | ¥12 | 9 折 | 不含 |
| SVIP | ¥30 | ¥25 | 8 折 | 包含 |

管理员可按套餐独立修改折扣，但所有 SVIP 套餐的应付折扣必须小于所有 VIP 套餐，且不能叠加优惠。套餐组合固定，不能删除后重新制造重复组合。

## 业务边界与一致性

### 购买与权益

1. 身份来自服务端会话，客户端不能通过传入其他 `user_id` 代购或查询他人权益；管理员会话也不能当普通用户使用。
2. 钱包按整数分计算，兼容原 `users.balance` 元字段。扣款、购买流水、权益发放和授权记录处于同一个 SQLite `BEGIN IMMEDIATE` 事务中，任一步失败全部回滚。
3. 客户端在发送购买前保存 UUID 操作编号，结果不确定时重试同一个编号。`(user_id, operation_key)` 唯一约束与参数指纹保证重复请求不再次扣款；修改参数复用编号会被拒绝。重试返回原购买期限与金额，但钱包余额重新读取当前值，不覆盖后续消费产生的余额变化。
4. 同级未到期续购从已付费权益的最晚到期点延长；无有效权益时从当前时间开始。未到期跨等级购买暂不支持，需到期后再选等级，未擅自制定补差价或退款规则。
5. 期限以 UTC+8 自然月计算，月底不足时落在目标月最后一天，例如 1 月 31 日加一个月为 2 月末。同一周期的起点为上次周期终点，后续按该终点再加月。
6. 权益按时间段保存独立的等级、折扣与套餐版本。管理员改价/改折扣不重写已付费时间段；续购的新条款从新时间段开始生效。有效区间为 `[starts_at, expires_at)`。

### 自动续费

- 连续套餐购买弹窗有默认不勾选的独立授权框，显示金额和周期；未同意不能确认扣费。固定套餐不会新开续费授权；如果此前已经开启，固定续购也不会暗中替用户取消旧授权，用户应点“取消后续续费”。
- 自动续费状态和已付费权益分别保存，取消只停止以后扣费，不回收已付费时间。
- 服务端启动成功后检查到期订阅，之后每 30 秒检查一次，每批最多 100 条。前提是服务端进程运行、系统时钟正确；不依赖用户客户端在线。
- 每次扣费使用 `renewal_<subscription_id>_<next_due>` 唯一编号（该编号前缀不允许客户端购买使用）。同周期即使重启/重复扫描也只付一次。
- 管理员变更价格、折扣或上下架会让相关有效续费授权进入 `needs_confirmation`；新条款须用户再次确认，绝不静默涨价扣费。
- 余额不足进入 `insufficient_balance`，权益按原时间到期，页面提示续费已停止。之后充值不自动补扣，已到期需重新购买，未到期可重新确认续费。
- 服务停机跨过整个未购买周期时进入 `missed_cycle`，不追收整个已过去周期。若恢复时仍处在首个待续周期内，则按原到期点续当前周期、收该周期全额；这是教学实现的明确策略，真实运营需另行确定停机补偿。
- 取消和到期扣费在事务边界串行执行：先取消则不扣，已扣完再取消则保留刚购买的周期。

### 充电优惠

预约成功事务内查询当时有效权益，将 `membership_level`、`discount_bps`、`membership_version` 与充电单价一起写入订单。后续开始、断线恢复、实时推送、首次结算、余额不足后重试结算都读取订单快照，不重新读取会员当前状态。

金额先将电量乘单价四舍五入到整数分，再按快照折扣四舍五入得到实付分；优惠额为原价分减实付分。普通用户 `discount_bps=10000`，不打折。旧数据库订单迁移为普通用户、不追溯优惠；原已结算金额不变。

## AI 配置与限制

API Key 只放在**服务端进程环境变量**中，不放客户端、数据库、QSettings、Git 或日志。不要把真实 Key 发到聊天或提交配置文件。默认模型示例为 `glm-4.7-flash`，兼容接口还可配置通义等服务；可用模型和额度以供应商控制台为准。

| 环境变量 | 默认值 / 用途 |
| --- | --- |
| `EV_AI_API_KEY` | 必填；未配置时仅咨询显示未配置提示，其他会员功能正常 |
| `EV_AI_PROVIDER` | `glm`；可设 `qwen`，其他兼容供应商可设 `compatible` |
| `EV_AI_MODEL` | GLM 默认 `glm-4.7-flash`；Qwen 默认 `qwen3.7-flash`；其他供应商必须按其文档配置 |
| `EV_AI_BASE_URL` | GLM 默认 `https://open.bigmodel.cn/api/paas/v4`；Qwen 默认 `https://dashscope.aliyuncs.com/compatible-mode/v1`；不含末尾 `/chat/completions` |
| `EV_AI_ALLOW_LOCAL_HTTP` | 默认关闭；仅测试可设 `1` 允许回环地址 HTTP，不能用于公网服务 |

Linux 服务端示例（交互输入 Key 不写入命令历史）：

```bash
export EV_AI_PROVIDER=glm
export EV_AI_MODEL=glm-4.7-flash
read -rsp 'AI API Key: ' EV_AI_API_KEY
printf '\n'
export EV_AI_API_KEY
./build/bin/ev_server --host 127.0.0.1 --port 8888 --database ./build/demo/platform.sqlite3
```

代码不会自动读取 `.env`；如通过 Qt Creator 启动服务端，可在该运行配置的环境中设置这些变量。更改变量后重启服务端即可。

- 每次提问都核验连接绑定会话、正常账号和有效 SVIP；异步模型答复返回时再次核验，已到期/冻结/退出不会收到新的受限答复。
- 先用关键词检索已发布且未停用的知识；取最多 4 条、总正文不超过 14000 字作为参考，答案展示这些参考的来源及发布版本。当前是有界关键词检索，并非向量检索系统；知识最多 500 条，每条正文最多 12000 字。
- 不匹配知识的问题直接说明没有依据，不调用模型，不生成假答案。模型按系统指令限定充电租赁话题；模型输出仍可能出错，来源列表表示提供给模型的依据，不等于逐句事实保证。
- 知识草稿、用户资料、手机号、钱包余额和会话令牌不会作为系统数据发送给模型；用户自由输入的问题本身会发给供应商，因此输入框提示不要提供隐私资料。
- 每用户同时一问、全服最多四问、同会话至少间隔三秒。一次问题最多 2000 字，模型输出上限 900 tokens，响应限制 256 KiB，超时 25 秒；额度受限、无效响应或截断均给出错误和重试提示。
- 仅发送文本咨询请求，没有支付、订单修改或设备控制工具。不会下载来源网址或执行知识内容。
- 会话仅在服务端内存保存最近三轮，清空/退出/断开时清除；清空时尚未完成的旧答复不能重新污染会话。知识停用或版本变化后，正在进行的相关答复会被丢弃并提示重问。
- 正式模型地址强制 HTTPS，禁止自动重定向；回环 HTTP 仅供本地协议夹具。项目原有客户端 TCP 通信仍属于本地教学协议，未新增公网传输加密，不能直接作为公网商业会员系统上线。

## 持久化与接口

`DatabaseManager::migrate` 以新增表/字段方式迁移，不覆盖原模板、用户或订单；重复运行不恢复管理员已调整的套餐和知识。迁移真实运行库前仍应备份数据库。

| 表 | 内容 |
| --- | --- |
| `membership_plans` | 12 种当前套餐与乐观锁版本 |
| `membership_operations` | 带唯一操作编号的扣费流水及原结果，用于安全重试 |
| `membership_entitlements` | 已付费权益时间段及不可变折扣快照 |
| `membership_subscriptions` | 下一次续费时间、明确授权的条款、独立续费状态 |
| `membership_events` | 购买条款、单独续费授权、取消及续费成功/停止记录 |
| `knowledge_articles` | 草稿和发布快照分别存储 |
| `orders` 新增字段 | 会员等级、折扣、套餐版本、原价分 |

沿用已有协议封包和登录会话。会员请求/响应 `0x40/0x41`：`plans`、`status`、`purchase`、`set_renewal`；咨询 `0x50/0x51`：`ask`、`clear`。`purchase` 参数为 `plan_id`、`version`、`operation_key`、`renewal_consent`；客户端不能提交价格、到期时间或会员归属。

后台查询沿用 `AdminQuery`：`membership_plans`、`knowledge_list`；后台操作沿用 `AdminAction`：`membership_update`、`knowledge_save`、`knowledge_publish`、`knowledge_disable`，全部要求管理员角色。前台套餐查询仅返回已上架套餐。

`status` 返回当前权益、累计已付费到期时间、独立续费状态和最近 30 条本人购买/续费记录。充电/订单响应新增 `gross_fee_cent`、`discount_fee_cent`、`membership_level`、`discount_bps`，保留旧字段供现有客户端兼容。
