================================================================================
  大数据与机器学习 / 智能预测（UML-067 ~ UML-068，对应 B=67~68）
================================================================================

  中任务概述：
  本中任务定义模型预测流程——加载训练好的模型，对未来的
  充电需求、空闲桩分布、高峰时段进行预测。预测结果保存为
  CSV文件，供大屏展示（UML-063）和智能应用（UML-069~070）
  使用。

  组件清单（本中任务涉及）：
  - 预测模块（Predictor，Python脚本）
  - 训练好的模型（data/models/*.pkl）
  - 最新数据（data/processed/*.csv，用于生成预测特征）
  - 预测结果（data/predictions/*.csv）

  解耦设计：
  - 预测与训练分离：训练离线执行，预测加载已有模型
  - 多时间尺度预测：日级预测和小时级预测独立执行
  - 预测结果通过文件输出，供大屏和应用模块读取


------------------------------------------------------------
【UML-067】多时间尺度负荷预测
------------------------------------------------------------

■ 场景
  预测模块加载日负荷预测模型（demand_forecast.pkl），使用
  最新的历史充电量数据生成未来7天的充电量预测。预测结果
  包括每日预测值、置信区间上下限。预测结果保存为CSV文件，
  大屏通过 /prediction 接口读取并展示。

  多时间尺度的含义：
    - 短期预测：未来1天（今日剩余+明日）
    - 中期预测：未来7天（本周+下周初）
    - 长期预测：未来30天（月度趋势）
  （本项目以7天预测为核心，30天可作为扩展）

■ 参与者
  - 预测模块（DemandPredictor，Python脚本）
  - 日负荷预测模型（demand_forecast.pkl，ARIMA模型）
  - 最新时序数据（daily_kwh.csv）
  - 预测结果（predictions/demand_next7.csv）

■ 前置条件
  - UML-066 模型训练已完成，模型文件存在
  - UML-061 数据预处理已完成，最新数据可用

■ 处理流程
  1. 预测模块 → 数据存储管理器：加载 demand_forecast.pkl 模型
  2. 预测模块 → 数据存储管理器：加载 daily_kwh.csv（最新历史数据）
  3. 预测模块 → 预测模块：构造预测所需的输入特征：
     - 提取最近N天的充电量序列（N=模型所需的滞后阶数+窗口大小）
     - 构造未来7天的时间特征（星期几、是否周末等）
  4. 预测模块 → 预测模块：执行预测
     - 调用 ARIMA 模型的 forecast(steps=7) 方法
     - 生成未来7天的点预测值
     - 计算置信区间（默认95%置信度）：
       下限 = 预测值 - 1.96 × 标准误
       上限 = 预测值 + 1.96 × 标准误
  5. 预测模块 → 预测模块：组装预测结果
     日期列：预测日期（从明天开始，共7天）
     预测值列：predicted_kwh（预测充电量，度）
     下界列：lower_bound（置信区间下限）
     上界列：upper_bound（置信区间上限）
     置信度列：confidence（0.95）
  6. 预测模块 → 数据存储管理器：保存预测结果
     data/predictions/demand_next7.csv
  7. 预测模块 → 预测模块：记录预测日志
     （预测时间、模型版本、数据截至日期、预测耗时）

■ 预测结果格式（demand_next7.csv）
  date,predicted_kwh,lower_bound,upper_bound,confidence
  2026-09-04,4200.50,3500.20,4900.80,0.95
  2026-09-05,3800.30,3100.10,4500.50,0.95
  ...（共7行）

■ 多时间尺度扩展（可选）
  - 1天预测：forecast(steps=1)，用于当日运营决策
  - 7天预测：forecast(steps=7)，用于周度规划（核心）
  - 30天预测：使用更长周期的模型或叠加趋势，用于月度展望
  - 不同尺度的预测使用同一模型的不同步数，或分别训练模型

■ 异常处理
  - 模型文件不存在：记录错误，跳过预测，保留上次预测结果
  - 历史数据不足：数据点少于模型所需的最小长度（如<30天），
    使用简单移动平均作为替代预测
  - 预测失败（模型报错）：记录错误日志，使用基线方法
    （简单移动平均）生成降级预测

■ 输出
  - data/predictions/demand_next7.csv — 未来7天负荷预测
  - data/logs/predict.log — 预测日志

■ 关联
  - 前序：UML-066（模型训练，生成模型文件）
  - 数据输入：UML-061（数据预处理，daily_kwh.csv）
  - 后续：
    - UML-063（可视化大屏，通过 /prediction 接口展示预测曲线）
    - UML-070（运营负荷预警，基于预测结果判断是否过载预警）
    - UML-071（预测效果评估，对比预测值与实际值）
  - 说明：
    - 预测是离线批处理，每日执行1次
    - 预测结果通过文件传递，大屏读取文件展示
    - 预测精度随历史数据积累而提升


------------------------------------------------------------
【UML-068】空闲桩与高峰预测
------------------------------------------------------------

■ 场景
  预测模块加载高峰预测模型（peak_predict.pkl），预测未来
  24小时各时段的充电量和充电桩使用情况，识别高峰时段和
  空闲时段。同时结合各站点的历史使用规律，预测各站点
  在不同时段的空闲桩数量，为用户推荐低拥堵站点提供依据。

  预测内容：
    1）24小时充电量预测：未来24小时每小时的系统总充电量
    2）高峰时段识别：哪些时段是高峰（充电量高、桩紧张）
    3）站点级空闲桩预测：各站点在不同时段的预计空闲桩数量

■ 参与者
  - 预测模块（PeakPredictor，Python脚本）
  - 高峰预测模型（peak_predict.pkl）
  - 小时级时序数据（hourly_kwh.csv）
  - 站点统计数据（station_daily.csv）
  - 预测结果（predictions/peak_hours.csv, predictions/idle_predict.csv）

■ 前置条件
  - UML-066 模型训练已完成
  - UML-061 数据预处理已完成

■ 处理流程

  A. 24小时充电量预测
    1. 预测模块 → 数据存储管理器：加载 peak_predict.pkl
    2. 预测模块 → 数据存储管理器：加载 hourly_kwh.csv
    3. loop 对每个小时（0~23）
       - 提取该小时的历史序列
       - 使用对应小时的ARIMA模型预测未来1步（即明天同一小时）
       - 保存预测值
    4. 预测模块 → 预测模块：组装24小时预测结果
       列：hour, predicted_kwh, lower_bound, upper_bound
    5. 预测模块 → 数据存储管理器：保存 peak_hours.csv

  B. 高峰时段识别
    1. 预测模块 → 预测模块：计算24小时预测值的均值
    2. 预测模块 → 预测模块：定义高峰阈值
       - 高峰：充电量 > 均值 × 1.5
       - 平峰：均值 × 0.8 ~ 均值 × 1.5
       - 低峰：充电量 < 均值 × 0.8
    3. 预测模块 → 预测模块：标记各时段的峰谷等级
       peak_level: peak / flat / valley
    4. 预测模块 → 预测模块：汇总高峰时段列表
       （如"早高峰7:00-9:00，晚高峰18:00-20:00"）

  C. 站点级空闲桩预测
    1. 预测模块 → 数据存储管理器：加载站点统计数据和桩数据
    2. loop 对每个站点
       - 获取该站点的总桩数（pile_count）
       - 获取该站点的历史小时利用率分布
       - 按小时预测利用率 = 历史同时段利用率 × 系统负荷系数
         （系统负荷系数 = 预测小时充电量 / 历史平均小时充电量）
       - 预测空闲桩数 = 总桩数 × (1 - 预测利用率)，取整
       - 确保空闲桩数 ≥ 0 且 ≤ 总桩数
    3. 预测模块 → 预测模块：组装站点-小时空闲桩矩阵
       行：站点，列：小时(0~23)，值：预计空闲桩数
    4. 预测模块 → 数据存储管理器：保存 idle_predict.csv

■ 预测结果格式

  peak_hours.csv：
  hour,predicted_kwh,peak_level,lower_bound,upper_bound
  0,50.2,valley,30.1,70.3
  1,35.8,valley,20.5,51.1
  ...
  8,320.5,peak,260.2,380.8
  ...
  19,280.3,peak,230.1,330.5
  ...（共24行）

  idle_predict.csv：
  station_id,station_name,hour_0,hour_1,...,hour_23
  1,东软园区站,5,6,...,3
  2,高新区站,4,4,...,2
  ...（每行一个站点，24列小时数据）

■ 应用场景
  - 用户端：展示各时段的空闲桩预测，引导用户错峰充电
  - 大屏：展示高峰时段预警（UML-070）
  - 推荐：为低拥堵站点推荐（UML-069）提供数据支撑
  - 运营：帮助管理员安排桩维护时间（选在低峰时段）

■ 异常处理
  - 模型加载失败：使用历史同时段均值作为预测（基线方法）
  - 站点数据不足：跳过该站点，或使用全站平均利用率估算
  - 预测值异常（负值或超大值）：截断到合理范围

■ 输出
  - data/predictions/peak_hours.csv — 24小时充电量预测+峰谷标记
  - data/predictions/idle_predict.csv — 各站点各时段空闲桩预测

■ 关联
  - 前序：UML-066（模型训练，高峰预测模型）
  - 数据输入：UML-061（hourly_kwh.csv, station_daily.csv）
  - 后续：
    - UML-063（可视化大屏，高峰预测展示）
    - UML-069（低拥堵站点推荐，使用空闲桩预测）
    - UML-070（运营负荷预警，基于高峰预测）
    - UML-071（预测效果评估）
  - 说明：
    - 高峰预测比日负荷预测更细粒度（小时级 vs 日级）
    - 站点级空闲桩预测是规则+预测的混合方法
      （简化实现，课程实践足够）


------------------------------------------------------------
  智能预测模块整体关系
------------------------------------------------------------

  训练好的模型（UML-066输出）
       │
       ├─ demand_forecast.pkl ──→ UML-067 多时间尺度负荷预测
       │                           输出：demand_next7.csv
       │                           用途：大屏预测曲线 / 运营预警
       │
       └─ peak_predict.pkl ──→ UML-068 空闲桩与高峰预测
                                 输出：peak_hours.csv + idle_predict.csv
                                 用途：高峰预警 / 站点推荐 / 错峰引导

  预测频率：每日1次（凌晨训练完成后）
  预测范围：未来7天（日级） + 未来24小时（小时级）
  传递方式：CSV文件 → 大屏数据服务（UML-058）读取 → 大屏展示
