================================================================================
  大数据与机器学习 / 智能应用（UML-069 ~ UML-070，对应 B=69~70）
================================================================================

  中任务概述：
  本中任务定义大数据分析的两个智能应用：低拥堵站点推荐
  （UML-069）和运营负荷预警（UML-070）。这两个应用将分析
  和预测的结果转化为实际业务价值——前者服务于用户端
  （提升充电体验），后者服务于管理端（辅助运营决策）。

  组件清单（本中任务涉及）：
  - 推荐引擎（RecommendationEngine，Python模块）
  - 预警引擎（AlertEngine，Python模块）
  - 预测结果（data/predictions/*.csv）
  - 站点统计数据（data/analysis/station_stats.csv）
  - 推荐结果（data/predictions/recommendations.csv）
  - 预警结果（data/predictions/alerts.csv）

  解耦设计：
  - 推荐和预警是两个独立的智能应用，各自独立计算
  - 推荐结果供用户端使用（充电站查询时展示推荐标签）
  - 预警结果供大屏和管理端使用（告警展示）
  - 两个应用都基于预测和分析结果，不直接访问业务数据库


------------------------------------------------------------
【UML-069】低拥堵站点推荐
------------------------------------------------------------

■ 场景
  推荐引擎基于各站点的历史使用数据、实时状态和高峰预测，
  计算每个充电站的"推荐度"综合评分，生成站点推荐列表。
  推荐的核心目标是引导用户选择拥堵程度低、体验好的站点，
  平衡各站点的负载，减少用户等待时间。

  推荐结果展示位置：
  - 用户端充电站查询列表（UML-018）：高推荐度的站点显示
    "推荐"标签
  - 大屏站点排名（UML-063）：展示推荐度Top站点

■ 参与者
  - 推荐引擎（RecommendationEngine，Python模块）
  - 站点统计数据（station_stats.csv）
  - 空闲桩预测（idle_predict.csv）
  - 充电桩实时状态（charging_piles 表，通过大屏数据服务获取）
  - 推荐结果（recommendations.csv）

■ 前置条件
  - UML-062 数据分析已完成（站点统计数据可用）
  - UML-068 空闲桩预测已完成（预测数据可用）

■ 推荐评分模型

  综合推荐度 = Σ(维度得分 × 权重)

  维度和权重：

  1. 拥堵程度（权重 30%）—— 最重要的因素
     - 指标：当前空闲桩比例 + 预测时段空闲桩比例
     - 计算：空闲桩数 / 总桩数
     - 得分：利用率越低，得分越高（反相关）
     - 公式：congestion_score = 1 - (current_utilization * 0.6
               + predicted_utilization * 0.4)

  2. 站点质量（权重 25%）
     - 指标：故障率、设备完好率
     - 计算：1 - fault_rate（故障率越低越好）
     - 得分：quality_score = 1 - fault_rate

  3. 价格因素（权重 15%）
     - 指标：充电单价与均价的比值
     - 计算：(平均单价 - 本站单价) / 平均单价
     - 得分：price_score = max(0, 1 - (price / avg_price))
     - 价格越低，得分越高

  4. 用户满意度（权重 15%）
     - 指标：用户复充率（回头客比例）作为满意度代理
     - 计算：return_user_rate = 重复充电用户数 / 总用户数
     - 得分：satisfaction_score = return_user_rate

  5. 设备便利性（权重 15%）
     - 指标：快充桩占比、总桩数
     - 计算：fast_ratio * 0.5 + min(pile_count/10, 1) * 0.5
     - 得分：convenience_score
       （快充桩越多、总桩数越多，越便利）

  综合得分：
  total_score = congestion_score * 0.30
              + quality_score * 0.25
              + price_score * 0.15
              + satisfaction_score * 0.15
              + convenience_score * 0.15

  得分范围：0 ~ 1，越高越推荐

■ 推荐理由生成
  对每个推荐站点，自动生成推荐理由（取得分最高的1~2个维度）：
  - 拥堵得分高 → "当前空闲桩充足，无需等待"
  - 质量得分高 → "设备完好率高，故障少"
  - 价格得分高 → "充电价格优惠"
  - 满意度得分高 → "广受用户好评"
  - 便利性得分高 → "快充桩多，充电速度快"

■ 处理流程
  1. 推荐引擎 → 数据存储管理器：加载站点统计数据（station_stats.csv）
  2. 推荐引擎 → 数据存储管理器：加载空闲桩预测（idle_predict.csv）
  3. 推荐引擎 → 大屏数据服务：获取充电桩实时状态（/pile-status）
     或直接从DAL读取
  4. 推荐引擎 → 推荐引擎：计算各维度得分
     （对每个站点，分别计算5个维度的得分）
  5. 推荐引擎 → 推荐引擎：计算综合得分并排序
     （按 total_score 从高到低排序）
  6. 推荐引擎 → 推荐引擎：生成推荐理由
     （取权重最高的1~2个维度作为理由）
  7. 推荐引擎 → 数据存储管理器：保存推荐结果
     data/predictions/recommendations.csv

■ 推荐结果格式（recommendations.csv）
  rank,station_id,station_name,total_score,congestion_score,
    quality_score,price_score,satisfaction_score,convenience_score,
    reason
  1,3,高新区充电站,0.89,0.92,0.95,0.70,0.85,0.80,
    "设备完好率高，故障少；当前空闲桩充足，无需等待"
  2,1,东软园区站,0.78,0.65,0.88,0.82,0.80,0.90,
    "快充桩多，充电速度快；充电价格优惠"
  ...（按得分排序）

■ 与用户端的集成
  用户端充电站查询（UML-018）时，可在响应中附加推荐信息：
  - 推荐站点显示"推荐"标签
  - 推荐理由在站点详情页显示
  - 列表中推荐站点排序优先（或用标识区分）

  实现方式：
  - 推荐结果每日更新，存入数据库或文件
  - 用户端查询站点时，服务端附加推荐得分和标签
  - 对用户端透明——用户感知到的是"推荐"标签和理由

■ 输出
  - data/predictions/recommendations.csv — 站点推荐排序列表
  - 推荐结果通过大屏数据服务的 /recommendations 接口对外提供

■ 关联
  - 前序：UML-062（数据分析，站点统计）、
    UML-068（空闲桩预测，拥堵数据）
  - 后续：
    - UML-063（可视化大屏，推荐站点展示）
    - 用户端充电站查询（UML-018，展示推荐标签）
  - 说明：
    - 推荐是离线计算，每日更新1次
    - 实时状态（当前空闲桩）作为补充因子，可在服务端查询时
      动态调整推荐排序（轻量级实时调整）


------------------------------------------------------------
【UML-070】运营负荷预警
------------------------------------------------------------

■ 场景
  预警引擎基于实时数据和预测数据，自动检测异常情况，生成
  预警信息。预警分为多个级别（高/中/低），不同级别触发
  不同的响应方式。预警结果展示在大屏（UML-063）上，
  辅助管理员及时发现和处理问题。

  预警类型：
    1）设备故障预警：充电桩故障且长时间未恢复
    2）负荷过载预警：预测未来某时段充电需求超过承载能力
    3）站点低利用率预警：某站点持续低利用率，运营效率低下
    4）营收异常预警：日营收大幅低于预期，可能存在异常

■ 参与者
  - 预警引擎（AlertEngine，Python脚本）
  - 实时业务数据（DAL查询）
  - 预测数据（demand_next7.csv, peak_hours.csv）
  - 历史统计数据（analysis/*.csv）
  - 预警结果（alerts.csv）

■ 前置条件
  - 实时数据可访问（DAL可用）
  - 预测数据已生成（UML-067~068）
  - 历史统计数据可用（UML-062）

■ 预警规则定义

  1. 设备故障预警（故障桩未处理）
     触发条件：
       - 充电桩状态为 fault
       - 且持续时间 > 24小时（从状态变更时间算起）
     预警级别：高（high）
     预警消息："充电桩 [桩编号]（[站点名]）已故障超过24小时，请及时处理"
     检查频率：每小时1次

  2. 负荷过载预警（需求超过承载）
     触发条件：
       - 预测明日峰值充电量 > 系统最大承载能力 × 0.9
       - （系统最大承载 = 所有桩功率之和 × 同时使用率）
     预警级别：中（medium）
     预警消息："预计明日 [时段] 充电需求将达到峰值，接近系统承载上限，建议做好应对准备"
     检查频率：每日1次（预测更新后）

  3. 站点低利用率预警
     触发条件：
       - 某站点连续7天平均利用率 < 10%
       - 且该站点桩数 ≥ 3（排除只有1~2个桩的小站）
     预警级别：中（medium）
     预警消息："[站点名] 连续7天利用率低于10%，建议分析原因并优化运营"
     检查频率：每日1次

  4. 营收异常预警
     触发条件：
       - 昨日实际营收 < 近7日平均营收 × 0.5
       - （排除节假日等已知因素，简化版不排除）
     预警级别：低（low）
     预警消息："昨日营收较近7日均值下降超过50%，请关注是否存在异常"
     检查频率：每日1次

  5. 新用户增长异常（可选）
     触发条件：
       - 近7日新注册用户数环比增长 > 50% 或下降 > 30%
     预警级别：低（low）
     检查频率：每日1次

■ 预警级别与响应
  - 高（high）：红色，需要立即处理
    - 大屏顶部闪烁提示
    - 预警列表置顶
  - 中（medium）：黄色，需要关注
    - 大屏预警列表黄色背景
    - 正常滚动展示
  - 低（low）：灰色，仅供参考
    - 大屏预警列表灰色背景
    - 可折叠展示

■ 处理流程
  1. 预警引擎 → 数据存储管理器：加载历史统计数据
  2. 预警引擎 → 数据存储管理器：加载预测数据
  3. 预警引擎 → DAL：查询实时数据（桩状态、今日订单等）
  4. loop 遍历各类预警规则
     - 预警引擎 → 预警引擎：检查触发条件
     - alt 满足触发条件
       - 预警引擎 → 预警引擎：生成预警记录
         { alert_type, severity, target, message,
           timestamp, status: "active" }
     else 不满足
       - 跳过
     end
  5. 预警引擎 → 预警引擎：汇总所有活跃预警，按级别排序
     （高优先级在前，同级别按时间倒序）
  6. 预警引擎 → 数据存储管理器：保存预警结果
     data/predictions/alerts.csv
  7. 预警引擎 → 预警引擎：记录预警日志

■ 预警结果格式（alerts.csv）
  alert_id,alert_type,severity,target,message,timestamp,status
  A001,fault,high,充电桩 #A-03,充电桩故障超过24小时未处理,2026-09-03T08:00:00,active
  A002,low_usage,medium,南门充电站,站点连续7天利用率低于10%,2026-09-03T06:00:00,active
  A003,revenue_anomaly,low,全站,昨日营收较均值下降50%,2026-09-03T01:00:00,active

■ 预警生命周期
  - 活跃（active）：问题存在，持续展示
  - 已处理（resolved）：问题已解决，从活跃列表移除
  - 已忽略（ignored）：管理员确认无需处理，暂时不提示

  状态流转：
    active → resolved（问题解决，如故障桩已重启）
    active → ignored（管理员忽略）
    ignored → active（问题升级或再次触发）

  （注：课程实践中可简化为只展示active预警，不做状态管理）

■ 输出
  - data/predictions/alerts.csv — 活跃预警列表
  - 预警结果通过大屏数据服务的 /alerts 接口对外提供

■ 关联
  - 前序：UML-062（数据分析，历史统计）、UML-067~068（预测数据）
  - 后续：UML-063（可视化大屏，预警列表展示）
  - 说明：
    - 预警是离线+准实时的混合模式
    - 设备故障预警：每小时检查（准实时）
    - 其他预警：每日检查1次（离线）
    - 预警结果通过大屏展示，不主动推送通知给管理员
      （管理员需主动查看大屏或管理端）

  智能应用模块整体关系
------------------------------------------------------------

  预测数据（UML-067~068）
  分析数据（UML-062）

       │
       ├─→ UML-069 低拥堵站点推荐

       │     服务对象：用户端（充电站查询推荐标签）+ 大屏

       │
       └─→ UML-070 运营负荷预警

  将大数据分析的结果转化为实际业务价值。
