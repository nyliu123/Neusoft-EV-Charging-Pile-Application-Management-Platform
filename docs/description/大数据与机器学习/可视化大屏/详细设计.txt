================================================================================
  大数据与机器学习 / 可视化大屏（UML-063 ~ UML-064，对应 B=63~64）
================================================================================

  中任务概述：
  本中任务定义大数据可视化大屏的前端展示和数据刷新机制。
  大屏是面向决策者的Web应用，通过HTTP从大屏数据服务（UML-058）
  获取数据，使用ECharts渲染丰富的图表。大屏包含实时业务概览、
  充电桩状态分布、营收趋势、站点利用率、预测趋势、异常预警
  等多个模块，定时自动刷新数据。

  组件清单（本中任务涉及）：
  - 大屏前端（Web应用，HTML/CSS/JavaScript + ECharts）
  - 大屏数据服务（BigScreenAPI，HTTP接口，见UML-058）
  - ECharts 图表库（前端可视化引擎）
  - Axios/fetch（HTTP请求库）

  解耦设计：
  - 大屏是纯前端展示层，只通过HTTP API获取数据，不直接访问数据库
  - 大屏与管理端经营看板（UML-035~037）的区别：
    - 经营看板：Qt管理端的内嵌功能，面向管理员，指标精简
    - 大屏：独立Web应用，面向决策者/展示墙，指标丰富+含预测
  - 大屏不包含业务操作（只读展示），所有控制在管理端执行

■ 参与者
  - 决策者/观众（actor，观看大屏的人）
  - 大屏前端（Web页面，ECharts渲染）
  - 大屏数据服务（BigScreenAPI，HTTP接口，UML-058）

■ 前置条件
  - 大屏数据服务已启动（UML-058）
  - 浏览器可访问大屏HTML文件和数据服务
  - ECharts库已加载（通过CDN或本地文件）

■ 大屏模块详细设计

  模块1：核心指标卡片（顶部4个数字）
    - 总站点数：来自 /overview 的 total_stations
    - 总充电桩数：来自 /overview 的 total_piles
    - 注册用户数：来自 /overview 的 total_users
    - 累计营收：来自 /overview 的 total_revenue
    - 设计：大号数字 + 图标 + 单位，科技感边框，数字滚动动画

  模块2：充电桩状态分布
    - 数据来源：/pile-status
    - 图表类型：环形图（doughnut chart）
    - 数据系列：空闲(绿色)、使用中(蓝色)、已预约(黄色)、故障(红色)
    - 中心显示：当前正在充电数 / 总桩数
    - 动画：首次加载扇形展开动画

  模块3：营收趋势（近7日）
    - 数据来源：/revenue-trend?days=7
    - 图表类型：折线图（line chart），带面积填充
    - 横轴：日期
    - 纵轴：营收金额（元）
    - 设计：渐变色线条，数据点标记，平滑曲线

  模块4：充电站利用率排名
    - 数据来源：/station-utilization
    - 图表类型：横向柱状图（bar chart）
    - 纵轴：站点名称
    - 横轴：利用率（百分比）
    - 排序：利用率从高到低
    - 设计：渐变色柱形，数值标签在柱右侧

  模块5：未来7日充电量预测
    - 数据来源：/prediction?type=charging_demand
    - 图表类型：折线图，包含：
      - 历史数据（过去7天，实线）
      - 预测数据（未来7天，虚线）
      - 置信区间（预测值 ± 误差范围，半透明填充）
    - 设计：历史数据蓝色，预测数据橙色，置信区间淡橙色

  模块6：实时异常预警
    - 数据来源：/alerts
    - 展示形式：垂直滚动列表
    - 每条预警包含：级别（高/中/低）、类型、目标、消息、时间
    - 颜色：高优先级红色背景，中优先级黄色背景，低优先级灰色
    - 滚动效果：自动向上滚动，新告警从底部滑入

  模块7：顶部状态栏
    - 大屏标题
    - 当前时间（实时时钟，每秒更新）
    - 数据更新时间（最近一次刷新的时间戳）
    - 刷新状态指示器（刷新中/已完成/错误）

■ 处理流程（页面初始化）
  1. 浏览器 → 大屏前端：加载大屏HTML页面
  2. 大屏前端 → 大屏前端：加载ECharts库和样式
  3. 大屏前端 → 大屏数据服务：并行发送多个HTTP请求：
     - GET /overview（核心指标）
     - GET /pile-status（桩状态分布）
     - GET /revenue-trend?days=7（营收趋势）
     - GET /station-utilization（站点利用率）
     - GET /prediction?type=charging_demand（预测数据）
     - GET /alerts（异常预警）
  4. 大屏数据服务 → 大屏前端：返回各接口的JSON响应
  5. 大屏前端 → 大屏前端：初始化所有ECharts实例，
     配置option，渲染图表
  6. 大屏前端 → 决策者：大屏完整展示

■ 交互功能
  - 鼠标悬停：图表显示tooltip（详细数据）
  - 图例点击：可切换显示/隐藏某系列数据
  - 全屏模式：双击切换全屏/窗口模式
  - 主题切换：深色/浅色（默认深色科技风）

■ 输出
  - 完整的可视化大屏页面，包含6+个图表模块
  - 深色科技风格UI，适合大屏展示

------------------------------------------------------------
【UML-064】数据刷新
------------------------------------------------------------

■ 场景
  大屏页面加载完成后，按照设定的时间间隔自动刷新数据，保证
  展示的信息是最新的。刷新时通过HTTP请求获取最新数据，
  更新ECharts图表的series数据，实现平滑过渡动画。

■ 参与者
  - 大屏前端（Web页面，定时器触发刷新）
  - 大屏数据服务（BigScreenAPI，HTTP接口）
  - ECharts 图表实例

■ 前置条件
  - UML-063 大屏已初始化，图表已渲染
  - 大屏数据服务可用

■ 刷新策略
  - 刷新间隔：默认30秒（可配置，见 UML-058 的 /config 接口）
  - 刷新方式：全量刷新（所有模块同时请求最新数据）
  - 错误处理：
    - 单次请求失败：显示告警提示，保留上一次数据，不中断刷新
    - 连续3次失败：显示"数据服务异常"提示，延长刷新间隔到60秒
    - 恢复成功：恢复30秒间隔

■ 处理流程
  1. 大屏前端 → 大屏前端：页面初始化完成，启动刷新定时器
     （setInterval，间隔30秒）
  2. loop 每次刷新
     - 大屏前端 → 大屏前端：更新状态栏为"刷新中..."
     - 大屏前端 → 大屏数据服务：并行发送所有数据请求
       （同初始化时的6个接口）
     - alt 所有请求成功
       - 大屏数据服务 → 大屏前端：返回最新数据
       - 大屏前端 → ECharts：调用 setOption 更新各图表数据
       - ECharts → 大屏前端：图表平滑过渡到新数据
         （ECharts内置的animation过渡）
       - 大屏前端 → 大屏前端：更新状态栏为"已更新"，
         更新"数据更新时间"
     else 部分请求失败
       - 大屏前端 → 大屏前端：成功的模块更新数据
       - 大屏前端 → 大屏前端：失败的模块保留上次数据，
         状态栏显示"部分数据更新失败"
       - 大屏前端 → 大屏前端：记录失败次数
       - alt 连续失败 >= 3次
         - 大屏前端 → 大屏前端：延长刷新间隔（30秒→60秒）
         - 大屏前端 → 大屏前端：状态栏显示"数据服务异常，已降低刷新频率"
       end
     end
  end

  3. alt 恢复成功（从失败状态恢复）
     - 大屏前端 → 大屏前端：检测到本次刷新成功且之前是降级状态
     - 大屏前端 → 大屏前端：恢复30秒刷新间隔
     - 大屏前端 → 大屏前端：状态栏恢复正常

  4. alt 管理员手动刷新
     - 管理员 → 大屏前端：点击"立即刷新"按钮
     - 大屏前端 → 大屏前端：取消当前定时器计时，立即执行一次刷新
     - 大屏前端 → 大屏前端：刷新完成后重置定时器

■ 各模块刷新特性
  - 核心指标卡片：数字滚动动画（从旧值滚动到新值）
  - 桩状态饼图：扇形角度平滑过渡
  - 营收趋势折线：折线形状平滑过渡，新增点从右滑入
  - 站点利用率柱状图：柱高动画变化，排序变化时重新排列
  - 预测折线图：预测曲线平滑更新
  - 预警列表：新预警从底部滑入，旧预警向上滚动

■ 性能优化
  - 请求合并：所有接口并行请求，减少总等待时间
  - 防抖：手动刷新按钮防抖（防止连续点击）
  - 缓存：如果数据未变化（内容相同），不触发图表重绘
  - 降级策略：服务异常时自动降低刷新频率，减少无效请求

■ 输出
  - 大屏数据每30秒自动更新
  - 图表平滑过渡，无闪烁
  - 服务异常时优雅降级

■ 关联
  - 前序：UML-063（大屏已初始化）
  - 数据来源：UML-058（大屏数据服务的各个HTTP接口）
  - 说明：
    - 刷新机制保证大屏数据的时效性
    - 30秒间隔是"准实时"级别——对于充电桩运营监控足够
    - 与Socket的实时推送不同，HTTP轮询更简单可靠，
      适合大屏这种只读展示场景
