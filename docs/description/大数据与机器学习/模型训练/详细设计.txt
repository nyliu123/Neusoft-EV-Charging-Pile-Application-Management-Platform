================================================================================
  大数据与机器学习 / 模型训练（UML-065 ~ UML-066，对应 B=65~66）
================================================================================

  中任务概述：
  本中任务定义预测模型的训练流程，包括特征工程（UML-065）和
  时序模型训练（UML-066）。训练好的模型用于后续的智能预测
  （UML-067~068）和智能应用（UML-069~070）。

  模型训练是离线批处理过程，基于历史数据训练模型，训练好的
  模型保存到文件，供预测时加载使用。训练频率为每日1次
  （凌晨数据采集和预处理完成后）。

  组件清单（本中任务涉及）：
  - 特征工程模块（FeatureEngineer，Python脚本）
  - 模型训练模块（ModelTrainer，Python脚本，基于scikit-learn/statsmodels）
  - 预处理数据（data/processed/*.csv，训练输入）
  - 训练好的模型（data/models/*.pkl，训练输出）
  - 模型元数据（model_meta.json，记录模型参数、训练时间、评估指标）

  解耦设计：
  - 特征工程和模型训练分离：特征是输入，训练是过程，模型是输出
  - 模型训练与预测分离：训练离线执行，预测在线/离线加载模型
  - 多种模型可替换：ARIMA、Prophet、线性回归等，通过配置选择
  - 模型版本管理：每次训练保存模型文件和元数据，支持回滚


------------------------------------------------------------
【UML-065】训练特征
------------------------------------------------------------

■ 场景
  特征工程模块从预处理后的时序数据中提取模型训练所需的特征
  和标签。不同的预测任务（负荷预测、高峰预测等）需要不同的
  特征组合。本任务定义各预测任务的特征集和标签构造方法。

■ 参与者
  - 特征工程模块（FeatureEngineer，Python脚本）
  - 预处理数据（data/processed/daily_kwh.csv 等）
  - 训练数据集（data/processed/train_*.csv，特征+标签）

■ 前置条件
  - UML-061 数据预处理已完成

■ 特征集定义

  A. 日负荷预测特征集（用于多时间尺度负荷预测 UML-067）

    目标（标签 label）：未来第N天的总充电量（kwh）

    特征列表：
    1. 时间特征：
       - day_of_week：星期几（0-6，独热编码或正弦余弦编码）
       - is_weekend：是否周末（0/1）
       - is_workday：是否工作日（0/1，与周末相反）
       - month：月份（1-12）
       - day_of_month：日期（1-31）

    2. 历史滞后特征（lag features）：
       - lag_1：前1天的充电量
       - lag_2：前2天的充电量
       - lag_3：前3天的充电量
       - lag_7：前7天的充电量（上周同日）
       - lag_14：前14天的充电量

    3. 滚动统计特征（rolling features）：
       - rolling_mean_7：近7天平均充电量
       - rolling_std_7：近7天充电量标准差
       - rolling_mean_14：近14天平均充电量
       - rolling_max_7：近7天最大值
       - rolling_min_7：近7天最小值

    4. 趋势特征：
       - trend_7d：近7天的斜率（线性回归系数）
       - growth_rate：(lag_1 - lag_7) / lag_7（周环比增长率）

    5. 外部特征（可选）：
       - temperature：当日气温（如数据可用）
       - weather_type：天气类型（晴/雨/雪，如数据可用）
       - is_holiday：是否节假日（如数据可用）
       （注：本项目若无外部数据，可省略此部分）

  B. 小时负荷预测特征集（用于高峰预测 UML-068）

    目标：未来某小时的充电量（kwh）

    特征列表：
    1. 时间特征：
       - hour：小时（0-23，独热编码或正弦余弦编码）
       - day_of_week：星期几
       - is_weekend：是否周末
       - time_slot：时段分类（早高峰/午间/晚高峰/夜间/其他）

    2. 历史滞后特征：
       - lag_1h：前1小时充电量
       - lag_24h：前24小时同时段充电量
       - lag_168h：前168小时（上周同时段）充电量

    3. 滚动统计特征：
       - rolling_mean_24h：近24小时平均
       - rolling_mean_168h：近168小时（一周）平均

    4. 日累计特征：
       - daily_total_sofar：当日截至当前小时的累计充电量

  C. 站点推荐特征集（用于低拥堵站点推荐 UML-069）

    目标：站点的"推荐度"（综合评分）

    特征列表：
    1. 站点基础属性：
       - pile_count：充电桩数量
       - fast_ratio：快充桩占比
       - avg_power：平均功率
       - price_per_kwh：充电单价

    2. 站点使用特征：
       - utilization_rate：平均利用率
       - peak_usage_rate：高峰时段利用率
       - avg_wait_time：平均等待时间（估算）
       - total_orders：总订单数

    3. 站点质量特征：
       - fault_rate：故障率
       - avg_rating：平均评分（如有评分系统）
       - user_satisfaction：用户满意度（基于复充率估算）

    4. 拥堵特征：
       - congestion_level：拥堵等级（0-1，基于利用率）
       - peak_congestion：高峰时段拥堵程度
       - idle_ratio：空闲时段占比

■ 特征构造流程
  1. 特征工程模块 → 数据存储管理器：加载预处理数据
  2. 特征工程模块 → 特征工程模块：按任务类型构造特征：
     a）时间特征：从时间戳提取，独热编码或周期编码
     b）滞后特征：shift() 函数生成
     c）滚动特征：rolling() 函数计算
     d）趋势特征：滚动窗口内的线性回归斜率
  3. 特征工程模块 → 特征工程模块：构造标签（目标变量）：
     - 日预测：label = 充电量.shift(-N)（未来第N天）
     - 小时预测：label = 充电量.shift(-N)（未来第N小时）
  4. 特征工程模块 → 特征工程模块：特征选择（可选）：
     - 计算特征与标签的相关性
     - 移除高度相关的冗余特征（VIF或相关系数）
     - 保留Top-K重要特征
  5. 特征工程模块 → 特征工程模块：数据划分：
     - 训练集：前80%的时序数据
     - 验证集：中间10%（用于调参）
     - 测试集：最后10%（用于最终评估）
     （注：时序数据不能随机划分，必须按时间顺序划分）
  6. 特征工程模块 → 数据存储管理器：保存训练数据集：
     - train_demand.csv（日负荷预测训练集）
     - train_peak.csv（高峰预测训练集）
     - train_recommend.csv（推荐模型训练集）

■ 特征工程输出
  - data/processed/train_demand.csv — 日负荷预测训练集
  - data/processed/train_peak.csv — 小时负荷/高峰预测训练集
  - data/processed/train_recommend.csv — 推荐模型训练集
  - 每个文件包含：特征列 + 标签列 + 时间列

■ 关联
  - 前序：UML-061（数据预处理，读取processed/）
  - 后续：UML-066（时序模型训练，读取训练数据集）
  - 说明：特征工程是模型效果的关键——"特征决定上限，模型逼近上限"


------------------------------------------------------------
【UML-066】时序模型训练
------------------------------------------------------------

■ 场景
  模型训练模块读取特征工程输出的训练数据集，使用时序预测
  算法训练预测模型。训练完成后，模型保存为文件，同时记录
  模型元数据（参数、训练时间、评估指标）。

  本系统训练两类模型：
    1）日负荷预测模型：预测未来7天的每日充电量
    2）小时高峰预测模型：预测未来24小时各时段的充电量和高峰

  选用的算法：
    - 主模型：ARIMA（自回归积分滑动平均）——经典时序预测算法
    - 备选：Prophet（Facebook开源，适合有季节性的时序）
    - 基线：简单移动平均（SMA）——作为对比基准
    （注：本项目可先用ARIMA实现，作为课程实践足够）

■ 参与者
  - 模型训练模块（ModelTrainer，Python脚本）
  - 训练数据集（data/processed/train_*.csv）
  - 训练好的模型（data/models/*.pkl）
  - 模型元数据（data/models/model_meta.json）

■ 前置条件
  - UML-065 特征工程已完成，训练数据集已生成

■ 模型1：日负荷预测模型（demand_forecast.pkl）

  目标：预测未来7天的每日总充电量

  算法：ARIMA(p, d, q)
    - p：自回归阶数（使用ACF/PACF分析或自动选择）
    - d：差分阶数（通常1或2，使序列平稳）
    - q：移动平均阶数

  训练流程：
  1. 模型训练模块 → 数据存储管理器：加载 train_demand.csv
  2. 模型训练模块 → 模型训练模块：数据准备
     - 提取训练集的充电量序列（y_train）
     - 提取验证集的充电量序列（y_val）
  3. 模型训练模块 → 模型训练模块：平稳性检验
     - ADF检验（Augmented Dickey-Fuller test）
     - 若不平稳，进行差分（d=1 或 d=2）
  4. 模型训练模块 → 模型训练模块：参数选择
     - 方法1：根据ACF/PACF图人工选择p和q
     - 方法2：网格搜索（grid search），选择AIC最小的组合
     - 搜索范围：p ∈ {1,2,3,4,5,7}, d ∈ {0,1,2}, q ∈ {0,1,2,3}
  5. 模型训练模块 → 模型训练模块：训练ARIMA模型
     - 使用 statsmodels 的 ARIMA 类
     - 在训练集上拟合模型
  6. 模型训练模块 → 模型训练模块：验证集预测
     - 使用训练好的模型预测验证集
     - 计算验证集上的误差指标（MAE, RMSE, MAPE）
  7. alt 验证误差满足要求（如MAPE < 15%）
     - 模型训练模块 → 模型训练模块：使用训练集+验证集重新训练
       （用更多数据得到最终模型）
     - 模型训练模块 → 数据存储管理器：保存模型
       data/models/demand_forecast.pkl
     - 模型训练模块 → 数据存储管理器：保存元数据
       { model_name: "demand_forecast",
         algorithm: "ARIMA(5,1,2)",
         train_date: "2026-09-03",
         metrics: { MAE: 120.5, RMSE: 180.3, MAPE: 0.12 },
         features: ["lag_1","lag_7","rolling_mean_7",...],
         forecast_horizon: 7 }
   else 验证误差不满足要求
     - 模型训练模块 → 模型训练模块：尝试其他参数或算法
     - 若仍不满足，记录警告，使用当前最优模型
  end

■ 模型2：小时高峰预测模型（peak_predict.pkl）

  目标：预测未来24小时每小时的充电量，识别高峰时段

  算法：ARIMA + 季节性分解（SARIMA，考虑日周期性和周周期性）
    - 季节性周期：24小时（日周期）和168小时（周周期）
    - 简化方案：对同时段数据分别建模（24个独立模型）
      或使用SARIMA的seasonal参数

  训练流程（简化版：24个独立ARIMA模型）：
  1. 模型训练模块 → 数据存储管理器：加载 train_peak.csv
  2. loop 对每个小时（0~23）
     - 提取该小时的充电量时序（每天同一小时的数据）
     - 训练一个ARIMA模型
     - 验证并保存
  3. 模型训练模块 → 模型训练模块：高峰识别规则
     - 定义：充电量 > 日均值 × 1.5 的时段为高峰时段
     - 或使用K-means聚类将24小时分为高/中/低峰
  4. 模型训练模块 → 数据存储管理器：保存模型
     data/models/peak_predict.pkl（包含24个小时模型的列表）
  5. 模型训练模块 → 数据存储管理器：保存元数据

■ 模型3：推荐模型（recommendation.pkl，简化版）

  目标：为用户推荐合适的充电站（低拥堵、高质量）

  算法：加权评分（非机器学习，基于规则的推荐）
    - 综合利用率、故障率、单价、用户满意度等维度
    - 各维度权重可配置
    - 输出推荐排序和推荐理由

  （注：课程实践中可先用规则推荐，复杂度适中且效果可解释。
   若后续扩展，可升级为协同过滤或强化学习）

■ 训练调度
  - 频率：每日1次（凌晨3:00，数据采集和预处理完成后）
  - 触发方式：cron定时任务 或 上游任务完成后触发
  - 训练耗时：预计5~15分钟（取决于数据量和算法复杂度）
  - 版本管理：每次训练生成新模型文件，保留最近3个版本

■ 输出
  - data/models/demand_forecast.pkl — 日负荷预测模型
  - data/models/peak_predict.pkl — 高峰预测模型
  - data/models/recommendation.pkl — 推荐模型
  - data/models/model_meta.json — 所有模型的元数据
