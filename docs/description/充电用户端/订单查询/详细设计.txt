================================================================================
  充电用户端 / 订单查询（UML-033，对应 B=33）
================================================================================

  中任务概述：
  用户在首页点击"我的订单"入口，查看个人历史充电订单列表。列表
  展示每个订单的关键信息：订单号、充电站名、充电桩编号、状态、
  充电量、费用、时间。订单按时间倒序排列。

  组件清单（本中任务涉及）：
  - 用户（actor）
  - 订单列表界面（QT 列表页，展示订单卡片）
  - 订单服务（服务端，处理订单查询）
  - 订单表（orders）
  - 充电站表（charging_stations，关联查询站名）
  - 充电桩表（charging_piles，关联查询桩编号）
  - 用户端全局状态（提供 user_id 和登录态校验）

  解耦设计：
  - 订单服务独立于充电服务，只负责查询，不修改订单状态
  - 订单查询读取的数据由充电流程（UML-025~032）产生，两个模块
    通过共享订单表实现弱耦合，无直接调用关系
  - 订单列表界面只展示数据，不触发任何状态变更操作


------------------------------------------------------------
【UML-033】个人订单列表
------------------------------------------------------------

■ 场景
  用户在首页点击"我的订单"入口，进入订单列表页面。页面展示该用户
  的所有充电订单，按预约时间倒序排列。每条订单显示：订单号、
  充电站名称、充电桩编号、订单状态（预约中/充电中/待结算/已结算/
  已取消）、充电量（度）、费用（元）、预约时间。用户可点击某条
  订单查看更多详情（如充电时长）。

■ 参与者
  - 用户（actor）
  - 订单列表界面
  - 订单服务
  - 订单表（orders）

■ 前置条件
  - 用户已登录（UML-013）
  - 用户端全局状态持有 user_id

■ 处理流程
  1. 用户 → 订单列表界面：在首页点击"我的订单"入口
  2. 订单列表界面 → 用户端全局状态：校验登录态，获取 user_id
  3. 用户端全局状态 → 订单列表界面：返回 user_id, logged_in = true
  4. 订单列表界面 → 订单服务：发送 QUERY_ORDERS_REQ
     { user_id, session_id }
  5. 订单服务 → 订单表：SELECT o.order_id, o.status, o.reserve_time,
     o.start_time, o.end_time, o.charge_amount_kwh, o.price_per_kwh,
     o.total_fee,
     s.station_name, p.pile_number
     FROM orders o
     JOIN charging_stations s ON o.station_id = s.station_id
     JOIN charging_piles p ON o.pile_id = p.pile_id
     WHERE o.user_id = ?
     ORDER BY o.reserve_time DESC
  6. 订单表 → 订单服务：返回该用户所有订单记录（含关联的站名和桩编号）
  7. 订单服务 → 订单服务：为每个订单构造展示对象：
     - 状态文本映射：reserved→"预约中", charging→"充电中",
       pending_settlement→"待结算", settled→"已结算",
       cancelled→"已取消"
     - 计算充电时长（如有 start_time 和 end_time）：
       duration = end_time - start_time（小时）
  8. 订单服务 → 订单列表界面：返回 QUERY_ORDERS_RESP
     { orders: [
       { order_id, station_name, pile_number, status_text,
         charge_amount_kwh, total_fee, price_per_kwh,
         reserve_time, duration_hours },
       ...
     ] }
  9. alt 订单列表非空
     - 订单列表界面 → 订单列表界面：渲染订单卡片列表：
       每张卡片显示：订单号、站名、桩编号、状态标签（颜色区分：
       预约中=黄色、充电中=蓝色、待结算=橙色、已结算=绿色、
       已取消=灰色）、充电量"X.XX度"、费用"¥XX.XX"、预约时间
     - 订单列表界面 → 用户：展示订单列表，按时间倒序
     - alt 用户点击某订单卡片
       - 用户 → 订单列表界面：点击某条订单
       - 订单列表界面 → 用户：展开详情（显示充电时长、开始/结束时间、
         充电单价等更多字段）
     end
   else 无订单记录
     - 订单列表界面 → 用户：显示空状态"暂无充电订单"
  10. alt 用户返回
      - 用户 → 订单列表界面：点击返回
      - 订单列表界面 → 用户端首页：返回首页
  end

■ 输出
  - 展示用户所有充电订单列表，按时间倒序
  - 无订单时显示空状态

■ 关联
  - 前序：UML-013（登录状态维护）、UML-025~032（充电流程产生订单数据）
  - 后续：无直接后续（纯查询功能）
  - 数据：SELECT orders JOIN stations JOIN piles WHERE user_id
  - 说明：如果用户有待结算订单（status='pending_settlement'），
    订单卡片应突出显示"待结算"标签，提示用户前往结算。
    但结算操作在充电流程模块（UML-031）中处理，订单查询模块
    不触发结算。
