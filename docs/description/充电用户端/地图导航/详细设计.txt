================================================================================
  充电用户端 / 地图导航（UML-023 ~ UML-024，对应 B=23~24）
================================================================================

  中任务概述：
  用户在充电站列表（UML-021）中点击某站点的距离信息，系统调用
  腾讯地图完成导航。通过 QWebEngineView 加载腾讯地图 Web 页面，
  以用户当前位置为起点、目标充电站为终点，提供驾车/步行出行方式
  选择，点击导航按钮跳转至路线规划页面。

  组件清单（本中任务涉及）：
  - 用户（actor）
  - 导航界面（QT 页面，内嵌 QWebEngineView）
  - 腾讯地图API（外部Web API，地图渲染和路线规划）

  解耦设计：
  - 导航功能完全在客户端通过 QWebEngineView 实现，不经过服务端
  - 导航界面接收起点和终点坐标作为参数，与充电站查询模块松耦合
  - 导航不修改任何业务数据，是纯展示型功能


------------------------------------------------------------
【UML-023】加载腾讯地图
------------------------------------------------------------

■ 场景
  用户在充电站列表（UML-021）中点击某卡片的距离信息，系统打开
  导航界面。导航界面内嵌 QWebEngineView 组件，加载腾讯地图 Web
  页面。地图以用户当前位置（UML-019 获得的经纬度）为中心渲染。
  加载完成后在地图上同时标注起点（用户位置）和终点（目标充电站）。

■ 参与者
  - 用户（actor）
  - 导航界面（含 QWebEngineView 组件）
  - 腾讯地图API（Web 页面，通过 QWebEngineView 加载）

■ 前置条件
  - UML-021 中用户点击了某站点的距离信息
  - 已获得用户位置经纬度（UML-019）和目标站点经纬度（来自站点数据）

■ 处理流程
  1. 用户 → 充电站列表界面：点击某站点的距离信息
  2. 充电站列表界面 → 导航界面：传递起点和终点信息：
     - 起点：user_longitude, user_latitude（来自 UML-019）
     - 终点：station_longitude, station_latitude, station_name,
       station_address（来自站点列表数据）
  3. 导航界面 → 导航界面：初始化 QWebEngineView 组件
  4. 导航界面 → 腾讯地图API：加载腾讯地图 Web 页面 URL：
     https://apis.map.qq.com/tools/...
     参数中附带起终点经纬度
  5. alt 地图加载成功
     - 腾讯地图API → 导航界面：Web 页面渲染完成，地图显示
     - 导航界面 → 导航界面：在地图上标注起点（用户位置，蓝色标记）
       和终点（充电站位置，红色标记）
     - 导航界面 → 用户：显示地图页面，底部出现出行方式选择栏
     - （控制流转入 UML-024 出行方式选择）
   else 地图加载失败（网络问题或API不可用）
     - QWebEngineView → 导航界面：页面加载错误信号
     - 导航界面 → 用户：显示"地图加载失败，请检查网络后重试"，
       提供"重试"按钮
   end

■ 输出
  - 成功：地图页面渲染，标注起终点，进入出行方式选择
  - 失败：提示加载失败，可重试

■ 关联
  - 前序：UML-021（充电站卡片，用户点击距离信息触发）
  - 后续：UML-024（出行方式选择）
  - 外部依赖：腾讯地图 Web 页面（通过 QWebEngineView 加载）
  - 说明：QWebEngineView 是 QT 提供的 Web 引擎组件，可嵌入 QT
    应用中显示 Web 页面。地图渲染在 Web 引擎中完成，非 QT 原生绘制。


------------------------------------------------------------
【UML-024】出行方式选择
------------------------------------------------------------

■ 场景
  地图加载完成后（UML-023），页面底部出现出行方式选择栏，包含
  "驾车"和"步行"两个选项。用户选择出行方式后点击"开始导航"
  按钮，腾讯地图在 Web 页面中渲染路线规划结果（预计时间、距离、
  路线轨迹）。

■ 参与者
  - 用户（actor）
  - 导航界面（含 QWebEngineView 和出行方式选择控件）
  - 腾讯地图API（Web 页面内路线规划）

■ 前置条件
  - UML-023 地图已加载，起终点已标注

■ 处理流程
  1. 导航界面 → 用户：显示出行方式选择栏：
     - "驾车"按钮（默认选中）
     - "步行"按钮
     - "开始导航"按钮
  2. 用户 → 导航界面：选择出行方式（驾车/步行），点击"开始导航"
  3. 导航界面 → 腾讯地图API：调用路线规划
     （通过 JavaScript 调用腾讯地图 JS SDK 的方向服务）
     参数：起点坐标、终点坐标、出行方式
  4. alt 路线规划成功
     - 腾讯地图API → 导航界面：返回路线规划结果
       （预计距离、预计时间、路线折线）
     - 导航界面 → 导航界面：在地图上绘制路线（驾车=蓝色折线，
       步行=绿色折线），显示预计时间和距离
     - 导航界面 → 用户：地图上呈现完整路线规划，用户可查看路线
   else 无可行路线（如步行距离过远）
     - 腾讯地图API → 导航界面：返回无路线
     - 导航界面 → 用户：提示"当前出行方式无法到达目的地，
       请尝试切换出行方式"
   else 路线规划失败
     - 腾讯地图API → 导航界面：返回错误
     - 导航界面 → 用户：提示"路线规划失败，请稍后重试"
  5. alt 用户切换出行方式
     - 用户 → 导航界面：点击另一种出行方式
     - 导航界面 → 腾讯地图API：重新发起路线规划
     - （重复步骤4）
   else 用户返回
     - 用户 → 导航界面：点击返回按钮
     - 导航界面 → 充电站列表界面：返回站点列表
  end

■ 输出
  - 成功：地图上显示完整路线规划（距离、时间、路线）
  - 失败：提示无法规划路线

■ 关联
  - 前序：UML-023（加载腾讯地图）
  - 后续：无直接后续（导航完成后用户通常返回充电站列表→进入充电流程）
  - 说明：导航功能是纯展示型，不产生业务数据变更。用户通过导航
    到达充电站后，回到应用选择充电桩进入充电流程。
