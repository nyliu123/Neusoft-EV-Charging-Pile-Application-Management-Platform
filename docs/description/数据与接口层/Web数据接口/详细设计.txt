================================================================================
  数据与接口层 / Web数据接口（UML-058，对应 B=58）
================================================================================

  中任务概述：
  本中任务定义大数据可视化大屏的数据服务接口。大数据大屏
  （UML-059~072的展示层）是 Web 前端应用（不同于充电用户端
  和PC运营管理端的 Qt/C++ 应用），通过 HTTP/REST 从服务端
  获取数据，使用 ECharts 渲染图表。

  本中任务是"数据与接口层"与"大数据与机器学习"两个大分类
  之间的桥梁——为大数据大屏提供标准化的数据查询接口。

  组件清单（本中任务涉及）：
  - 大屏数据服务（BigScreenAPI，服务端HTTP接口模块）
  - HTTP Server（轻量级HTTP服务，可内嵌于服务端或独立部署）
  - 大屏前端（Web应用，使用ECharts + Axios/fetch）

  解耦设计：
  - 大屏数据服务通过 HTTP/REST 提供数据，与 Socket 通信完全分离
  - 大屏是只读视图，不执行任何写操作，不修改业务数据
  - 大屏数据服务复用DAL层查询方法，不直接执行SQL
  - 大屏数据的查询频率可控（定时刷新而非实时推送），
    避免频繁查询影响业务系统性能

  与已有两个系统的兼容关系：
  ┌─────────────┐     ┌─────────────┐
  │  充电用户端   │     │ PC运营管理端  │     ┌─────────────┐
  │ (Qt/C++/Socket)│   │ (Qt/C++/Socket)│   │  大数据大屏   │
  └──────┬──────┘     └──────┬──────┘     │ (Web/ECharts) │
         │                   │              └──────┬──────┘
         │  TCP Socket       │                     │ HTTP/REST
         │  (自定义协议)      │                     │ (标准HTTP)
         └─────────┬─────────┘                     │
                   │                          ┌────┴────┐
          ┌────────┴────────┐                 │大屏数据  │
          │  充电桩服务端     │ ←──复用DAL──── │ 服务API  │
          │ ├─ Socket层     │                 └─────────┘
          │ ├─ HTTP层(大屏)  │
          │ └─ DAL          │
          └────────┬────────┘
                   │
          ┌────────┴────────┐
          │  SQLite 数据库   │
          └─────────────────┘

  大屏数据服务与经营看板（UML-035~037）的区别：
  - 经营看板（PC管理端）：通过 Socket 查询，展示在 Qt 界面上，
    面向管理员，数据范围是"管理端关心的指标"
  - 大屏数据服务（大数据大屏）：通过 HTTP 查询，展示在 Web 大屏上，
    面向决策者，数据范围更广（含预测、推荐、预警等分析数据）
  - 两者查询底层都通过DAL访问同一数据库，但各自有独立的接口


------------------------------------------------------------
【UML-058】大屏数据服务
------------------------------------------------------------

■ 场景
  大数据大屏（Web前端）启动后，通过 HTTP/REST 向大屏数据服务
  发送查询请求，获取各类业务数据和分析结果。大屏前端按固定
  频率（默认30秒）自动刷新数据，也可手动触发刷新。

  大屏展示的数据分类：
    1）实时业务数据（复用DAL查询）：
       - 站点/设备/订单/营收统计（同经营看板但格式不同）
    2）分析数据（来自大数据模块 UML-059~072 的输出）：
       - 用电趋势预测、充电站推荐、异常预警等

■ 参与者
  - 大屏前端（Web应用，HTTP客户端）
  - 大屏数据服务（BigScreenAPI，HTTP服务端）
  - 数据访问层 DAL（复用，查询业务数据）
  - 分析数据集（CSV/模型文件，大数据分析结果）

■ 前置条件
  - 大屏数据服务已启动并监听HTTP端口（默认 8080）
  - 业务数据库可访问（DAL可用）
  - 大屏前端已知数据服务地址

■ REST API 接口定义

  基础URL: http://localhost:8080/api/bigscreen
  响应格式（统一JSON）:
  {
    "code": 0,           -- 0=成功，非0=失败
    "message": "ok",     -- 成功为"ok"，失败为具体错误
    "data": { ... }      -- 成功时包含数据，失败时为null
  }

  错误码定义:
    0  = 成功
    1001 = 参数错误（如日期格式不合法）
    1002 = 数据查询失败（数据库异常）
    1003 = 数据不可用（分析数据文件不存在）
    1004 = 服务内部错误

  ──────────────────────────────────────────
  接口1：实时业务概览
  GET /overview

  请求参数：无
  响应数据：
  {
    "code": 0, "data": {
      "total_stations": 5,
      "total_piles": 28,
      "total_users": 328,
      "total_orders": 156,
      "total_revenue": 9876.54,
      "total_kwh": 12345.67,
      "active_charging": 8,        -- 当前正在充电的桩数
      "fault_piles": 2,            -- 当前故障桩数
      "timestamp": "2026-09-03T11:00:00"
    }
  }

  -- 复用DAL: station_list_all(), pile_count_by_status(),
  -- user_count_all(), order_count_settled()
  -- 补充查询: 当前active_charging = COUNT(status='in_use')

  ──────────────────────────────────────────
  接口2：充电桩状态分布
  GET /pile-status

  请求参数：无
  响应数据：
  {
    "code": 0, "data": [
      { "status": "idle",      "label": "空闲",   "count": 15 },
      { "status": "reserved",  "label": "已预约",  "count": 3 },
      { "status": "in_use",    "label": "使用中",  "count": 8 },
      { "status": "fault",     "label": "故障",   "count": 2 }
    ]
  }

  -- 复用DAL: pile_count_by_status()

  ──────────────────────────────────────────
  接口3：营收趋势
  GET /revenue-trend?days={days}

  请求参数：days=7（默认7，可选1/7/30）
  响应数据：
  {
    "code": 0, "data": [
      { "date": "2026-08-28", "revenue": 234.50 },
      { "date": "2026-08-29", "revenue": 312.00 },
      ...
    ]
  }

  -- 复用DAL: order_revenue_by_date(start, end)

  ──────────────────────────────────────────
  接口4：充电站利用率
  GET /station-utilization

  请求参数：无
  响应数据：
  {
    "code": 0, "data": [
      { "station_name": "东软园区站", "pile_count": 6,
        "usage_rate": 0.67,         -- 利用率=使用中/总数
        "total_orders": 45 },
      ...
    ]
  }

  -- 复用DAL: station_list_all() + pile统计 + order统计

  ──────────────────────────────────────────
  接口5：预测数据（来自大数据分析模块）
  GET /prediction?type={type}

  请求参数：type=charging_demand（充电需求预测）
            type=revenue_forecast（营收预测）
  响应数据（充电需求预测）：
  {
    "code": 0, "data": {
      "dates": ["2026-09-04","2026-09-05",...],
      "predicted_kwh": [4200.5, 3800.3,...],
      "predicted_revenue": [3360.0, 3040.2,...],
      "model": "ARIMA",
      "accuracy": 0.92
    }
  }

  -- 读取分析数据集（CSV文件或模型输出）
  -- 大数据模块（UML-059~072）生成预测结果，
  -- 本接口读取结果文件并返回

  ──────────────────────────────────────────
  接口6：推荐充电站（来自推荐算法）
  GET /recommendations?station_id={id}

  请求参数：station_id（指定推荐关联的站点）
  响应数据：

    "code": 0, "data": [
      { "station_id": 3, "station_name": "高新区充电站",
        "score": 0.89, "reason": "高利用率+低故障率" },
      ...
    ]
  }

  -- 读取推荐算法输出（UML-065~068推荐模块的结果）

  ──────────────────────────────────────────
  接口7：异常预警
  GET /alerts

  请求参数：无
  响应数据：

    "code": 0, "data": [
      { "alert_type": "fault", "target": "充电桩 #A-03",
        "message": "充电桩故障超过24小时未处理",

  -- 异常检测算法（UML-069~072预警模块的结果）

  ──────────────────────────────────────────
  接口8：定时刷新控制
  GET /config

  请求参数：无
  响应数据：
  {
    "code": 0, "data": {
      "refresh_interval_sec": 30,   -- 刷新间隔
      "data_time_range": "realtime" -- 数据时效性标识
    }
  }

■ 处理流程
  1. 大屏前端 → 大屏数据服务：页面加载时发送 GET /overview
  2. 大屏数据服务 → 大屏数据服务：解析请求参数，校验合法性
  3. alt 参数合法
     - 大屏数据服务 → DAL：调用对应查询方法
     - DAL → SQLite：执行查询
     - SQLite → DAL → 大屏数据服务：返回查询结果
     - 大屏数据服务 → 大屏数据服务：组装统一响应格式
     - 大屏数据服务 → 大屏前端：返回 JSON 响应
     - 大屏前端 → 大屏前端：ECharts 渲染图表
   else 参数不合法
     - 大屏数据服务 → 大屏前端：返回
       { code: 1001, message: "参数错误：days应为正整数" }
   else 数据库查询异常
     - 大屏数据服务 → 大屏前端：返回
       { code: 1002, message: "数据查询失败" }
   else 分析数据文件不存在
     - 大屏数据服务 → 大屏前端：返回
       { code: 1003, message: "预测数据暂不可用" }
  end

  4. loop 定时刷新（每30秒）
     - 大屏前端 → 大屏数据服务：重新发送所有查询请求
     - 大屏前端 → 大屏前端：更新图表数据（平滑过渡动画）
  end

■ 认证与权限
  - 大屏数据服务当前不做认证（本地部署，非公网暴露）
  - 如需公网部署，应添加 API Key 或 Token 认证
  - 大屏是只读接口，即使无认证也不涉及数据安全风险

■ 性能控制
  - 刷新间隔30秒，避免频繁查询数据库
  - 聚合查询结果可缓存（服务端缓存30秒，减少数据库压力）
  - 预测/推荐/预警数据从文件读取，不每次重新计算
    （大数据模块定时生成结果文件，大屏接口读取文件返回）

■ 输出
  - 成功：返回统一格式的 JSON 响应，包含请求的数据
  - 失败：返回包含错误码和错误消息的 JSON 响应
  - 大屏前端根据错误码决定降级展示或重试

■ 关联
  - 前序：UML-047~053（DAL层提供查询能力）
  - 后续：UML-059~072（大数据与机器学习模块生成分析数据，
    本接口读取分析结果展示在大屏上）
  - 兼容性：
    - 大屏数据服务与 Socket 通信层（UML-054~055）完全独立
    - 大屏通过 HTTP 访问，不占用 Socket 连接和线程池资源
    - 复用同一DAL层和数据库，数据与两个Qt客户端一致
  - 与经营看板的区别：
    - 经营看板（UML-035~037）：通过Socket查询，在Qt管理端展示，
      面向管理员，指标较少（4个核心指标+营收趋势+桩状态）
    - 大屏数据服务（UML-058）：通过HTTP查询，在Web大屏展示，
      面向决策者，指标更丰富（含预测、推荐、预警等分析数据）
    - 两者数据来源相同（同一数据库），但展示方式和受众不同

  层次关系总结：
  - UML-047~053（业务数据库）：数据持久化，5张表+约束+事务，
    所有上层操作的数据基础
  - UML-054~055（Socket通信）：传输层，两个Qt客户端的通信通道
  - UML-056（并发处理）：服务端多线程，支撑多客户端并发
  - UML-057（腾讯地图接口）：外部API集成，地理编码+地图展示
  - UML-058（大屏数据服务）：HTTP接口，为大数据大屏提供数据

  对两个已有系统的兼容性保障：
  1. 充电用户端（UML-010~033）：
     - 通过 Socket（UML-054~055）与服务端通信
     - 数据通过 DAL（UML-047~053）读写
     - 地理编码通过地图接口适配器（UML-057）
     - 并发通过多线程服务（UML-056）支撑
  2. PC运营管理端（UML-034~046）：
     - 通过 Socket（UML-054~055）与服务端通信（同一机制，不同消息）
     - 数据通过 DAL（UML-047~053）读写
     - 新增充电站的地理编码通过地图接口适配器（UML-057）
     - 与用户端共享同一数据库，管理操作实时影响用户端
  3. 大数据大屏（UML-059~072）：
     - 通过 HTTP/REST（UML-058）获取数据
     - 复用 DAL 查询业务数据
     - 读取大数据模块生成的分析数据文件
     - 与两个Qt客户端完全独立，不占用Socket资源
