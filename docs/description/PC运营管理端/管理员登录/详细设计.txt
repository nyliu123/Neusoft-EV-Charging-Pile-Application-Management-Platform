================================================================================
  PC运营管理端 / 管理员登录（UML-034，对应 B=34）
================================================================================

  中任务概述：
  管理员打开PC运营管理端程序 → 输入用户名和密码 → 服务端验证 →
  维护管理端登录态。这是PC运营管理端的入口模块，后续所有管理操作
  （经营看板、桩管理、站管理、用户管理、订单管理）都依赖此模块
  建立的登录态。

  组件清单（本中任务涉及）：
  - 管理员（actor）
  - 管理端登录界面（QT 登录页，含用户名输入框、密码输入框、登录按钮）
  - 管理端服务（服务端，处理管理员登录请求）
  - 管理员表（admins，SQLite）
  - 管理端全局状态（维护 admin_id 和 admin_info）

  解耦设计：
  - 管理员登录模块只负责建立管理端登录态，不涉及其他业务逻辑
  - 登录态通过"管理端全局状态"传递给其他模块（经营看板、桩管理等），
    模块间不直接耦合
  - 管理端服务是管理端在服务端的唯一入口，处理所有管理端请求
  - 与用户端登录（UML-010~013）的"免密登录"不同，管理端采用
    "用户名+密码"验证机制，因为管理员权限高，需更强的身份认证

  与用户端登录的差异：
  - 用户端：手机号即可登录（免密），自动注册，无需密码
  - 管理端：用户名+密码验证，无注册入口（管理员账号由系统预置或DBA创建）
  - 默认管理员：username=admin, password=123456（预置在 admins 表中）


------------------------------------------------------------
【UML-034】账号密码验证
------------------------------------------------------------

■ 场景
  管理员打开PC运营管理端程序，进入登录界面。在输入框中键入
  用户名和密码并点击"登录"按钮。系统首先在前端进行非空校验，
  校验通过后将用户名和密码发送到服务端。服务端查询管理员表，
  比对用户名和密码是否匹配。验证通过后，服务端生成管理端会话
  标识 session_id，返回管理员信息，管理端保存登录态并跳转到
  经营看板首页。

■ 参与者
  - 管理员（actor）
  - 管理端登录界面（PC端 QT 界面，含用户名输入框、密码输入框、登录按钮）
  - 管理端服务（服务端业务逻辑层，处理管理员登录请求）
  - 管理员表（admins）

■ 前置条件
  - 管理端应用已启动，登录界面已渲染完成
  - 管理端已与服务端建立 Socket 连接（应用启动时自动连接）
  - admins 表中至少有一条预置管理员记录（默认 admin/123456）

■ 处理流程
  1. 管理员 → 管理端登录界面：在用户名输入框键入用户名（如 admin），
     在密码输入框键入密码（如 123456），点击"登录"按钮
  2. 管理端登录界面 → 管理端登录界面：读取输入框文本，执行前端校验：
     - 非空检查：用户名和密码均不能为空
     - 长度检查：用户名 1~50 字符，密码 1~255 字符
  3. alt 前端校验通过
     - 管理端登录界面 → 管理端登录界面：禁用登录按钮（防止重复提交），
       显示"正在登录..."
     - 管理端登录界面 → 管理端服务：发送 ADMIN_LOGIN_REQ
       { username: "输入的用户名", password: "输入的密码" }
     - 管理端服务 → 管理员表：查询 username = 输入用户名 的记录
     - alt 用户名存在且密码匹配
       - 管理员表 → 管理端服务：返回匹配的管理员记录
         （admin_id, username, create_time）
       - 管理端服务 → 管理端服务：生成 session_id，记录服务端会话
       - 管理端服务 → 管理端登录界面：返回 ADMIN_LOGIN_RESP
         { success: true, admin_info: { admin_id, username, session_id } }
       - 管理端登录界面 → 管理端全局状态：保存 admin_info 和 session_id，
         标记 admin_logged_in = true
       - 管理端登录界面 → 经营看板界面：切换到经营看板首页，加载首页组件
       - 管理端登录界面 → 管理员：看板渲染完成，在页面顶部弹出
         "登录成功"提示，3秒后自动消失
       - （控制流转入经营看板模块 UML-035~037）
     else 用户名不存在
       - 管理员表 → 管理端服务：无匹配记录
       - 管理端服务 → 管理端登录界面：返回 ADMIN_LOGIN_RESP
         { success: false, error: "用户名或密码错误" }
       - 管理端登录界面 → 管理员：弹窗提示"用户名或密码错误"，
         清空密码输入框，用户名输入框保留，停留登录页
       - 管理端登录界面 → 管理端登录界面：恢复登录按钮可用状态
     else 用户名存在但密码不匹配
       - 管理员表 → 管理端服务：返回管理员记录，但 password 字段
         与输入密码不一致
       - 管理端服务 → 管理端登录界面：返回 ADMIN_LOGIN_RESP
         { success: false, error: "用户名或密码错误" }
       - 管理端登录界面 → 管理员：弹窗提示"用户名或密码错误"
         （不区分"用户名不存在"和"密码错误"，防止枚举用户名）
       - 管理端登录界面 → 管理端登录界面：清空密码输入框，
         恢复登录按钮可用状态
     end
   else 用户名为空
     - 管理端登录界面 → 管理员：弹窗提示"请输入用户名"，停留登录页
   else 密码为空
     - 管理端登录界面 → 管理员：弹窗提示"请输入密码"，停留登录页
  end

  4. （登录成功后，管理端全局状态维护登录态）
  5. loop 管理员使用期间
     - 管理员执行任何管理操作（看板、桩管理、站管理等）时
     - 管理端各界面 → 管理端全局状态：检查 admin_logged_in == true
       且 session_id 非空
     - alt 已登录
       - 管理端全局状态 → 管理端各界面：返回 true，继续执行请求，
         在请求参数中附带 session_id 和 admin_id
     else 未登录（会话过期）
       - 管理端全局状态 → 管理端各界面：返回 false
       - 管理端各界面 → 管理员：弹窗提示"登录已过期，请重新登录"
       - 管理端各界面 → 管理端登录界面：跳转到登录界面
     end
  6. alt 管理员主动退出（点击退出按钮）
     - 管理员 → 管理端各界面：点击"退出登录"
     - 管理端各界面 → 管理端服务：发送 ADMIN_LOGOUT_REQ { session_id }
     - 管理端服务 → 管理端服务：清除服务端会话记录
     - 管理端服务 → 管理端各界面：返回 ADMIN_LOGOUT_RESP { success: true }
     - 管理端各界面 → 管理端全局状态：清除 admin_info 和 session_id，
       admin_logged_in = false
     - 管理端各界面 → 管理端登录界面：跳转到登录界面
   else 应用正常关闭
     - 管理端各界面 → 管理端服务：Socket 断开
     - 管理端服务 → 管理端服务：检测到连接断开，清除该 session_id
       的服务端会话记录
     - （下次启动需重新登录，登录态不持久化到磁盘）
  end

■ 输出
  - 成功：进入经营看板首页，管理端全局状态保存登录态（admin_id,
    username, session_id），所有后续管理操作可执行
  - 失败：弹窗提示"用户名或密码错误"，停留登录页可重新输入
  - 退出：清除登录态，返回登录界面

■ 关联
  - 前序：无（管理端入口的第一步）
  - 后续：UML-035~037（经营看板，登录后首页）、UML-038~039（充电桩管理）、
    UML-040~042（充电站管理）、UML-043~045（用户管理）、UML-046（订单管理）
  - 数据：读取 admins 表（SELECT），不修改数据
  - 业务规则：
    - 管理端采用用户名+密码验证（区别于用户端的免密登录）
    - 错误提示统一为"用户名或密码错误"，不区分用户名不存在和密码错误
    - 管理员账号无注册入口，由系统预置（默认 admin/123456）
    - 登录态不持久化，应用关闭后需重新登录
  - 安全考虑：
    - 密码在传输时通过 Socket 明文传输（本项目为课程实践，不涉及HTTPS）
    - 实际生产环境应改为哈希存储+加密传输，本项目简化处理
