================================================================================
  PC运营管理端 / 经营看板（UML-035 ~ UML-037，对应 B=35~37）
================================================================================

  中任务概述：
  管理员登录成功后，进入经营看板首页。经营看板是管理端的核心
  数据展示页面，通过聚合查询数据库中的订单、充电桩、用户数据，
  向管理员展示三类信息：
    1）核心经营指标（UML-035）：累计充电量、累计营收、注册用户数、
       累计充电次数——四个汇总数字卡片
    2）营收趋势（UML-036）：近7日每日营收的折线图
    3）充电桩状态统计（UML-037）：全量充电桩按状态分类的饼图/柱状图
  这三个子任务在经营看板首页加载时依次触发，也支持管理员手动刷新。

  组件清单（本中任务涉及）：
  - 管理员（actor）
  - 经营看板界面（管理端首页，含数字卡片区、折线图区、饼图区、刷新按钮）
  - 管理端服务（服务端，处理看板数据查询请求）
  - 订单表（orders）
  - 充电桩表（charging_piles）
  - 用户表（users）
  - 管理端全局状态（提供 admin_id 和 session_id）

  解耦设计：
  - 经营看板是只读查询模块，不修改任何业务数据
  - 三个子任务各自独立查询，互不依赖——某个查询失败不影响其他两个
  - 看板界面通过 ADMIN_QUERY_REQ 消息统一向服务端请求数据，
    以 type 字段区分查询类型
  - 看板数据均为聚合查询结果，不涉及单条记录的增删改


------------------------------------------------------------
【UML-035】核心经营指标
------------------------------------------------------------

■ 场景
  管理员登录成功后进入经营看板首页，页面顶部区域以四个数字卡片
  展示平台核心经营指标：
    1）累计充电量（度）—— 所有已结算订单的 charge_amount_kwh 之和
    2）累计营收（元）—— 所有已结算订单的 total_fee 之和
    3）注册用户数 —— users 表中所有用户的记录数
    4）累计充电次数 —— orders 表中所有订单的记录数
  这些指标让管理员一眼掌握平台的整体经营规模。看板首页加载时
  自动触发查询，管理员也可点击"刷新"按钮手动刷新。

■ 参与者
  - 管理员（actor）
  - 经营看板界面
  - 管理端服务
  - 订单表（orders）
  - 充电桩表（charging_piles）
  - 用户表（users）

■ 前置条件
  - UML-034 管理员登录已完成，管理端全局状态保存了 admin_id 和 session_id
  - 经营看板界面已渲染（登录后自动跳转）

■ 处理流程
  1. 经营看板界面 → 经营看板界面：页面加载完成，触发核心指标查询
     （管理员登录后自动执行，无需管理员手动操作）
  2. 经营看板界面 → 管理端服务：发送 ADMIN_QUERY_REQ
     { type: "dashboard_summary", session_id }
  3. 管理端服务 → 管理端服务：校验 session_id 有效性
  4. alt session_id 有效
     - 管理端服务 → 订单表：执行聚合查询
       SELECT
         SUM(charge_amount_kwh) AS total_kwh,
         SUM(total_fee) AS total_revenue,
         COUNT(*) AS total_orders
       FROM orders
       WHERE status = 'settled'
     - 管理端服务 → 用户表：执行计数查询
       SELECT COUNT(*) AS total_users FROM users
     - 管理端服务 → 管理端服务：组装四个指标数据
     - 管理端服务 → 经营看板界面：返回 ADMIN_QUERY_RESP
       { type: "dashboard_summary",
         data: { total_kwh: 12345.67, total_revenue: 9876.54,
                 total_users: 328, total_orders: 156 } }
     - 经营看板界面 → 经营看板界面：渲染四个数字卡片：
       - 卡片1：累计充电量 — 12,345.67 度
       - 卡片2：累计营收 — ¥9,876.54
       - 卡片3：注册用户数 — 328 人
       - 卡片4：累计充电次数 — 156 次
     - 经营看板界面 → 管理员：卡片渲染完成，显示在页面顶部区域
   else session_id 无效（会话过期）
     - 管理端服务 → 经营看板界面：返回 ADMIN_QUERY_RESP
       { success: false, error: "session_expired" }
     - 经营看板界面 → 管理员：弹窗提示"登录已过期，请重新登录"
     - 经营看板界面 → 管理端登录界面：跳转到登录界面
   else 数据库查询异常
     - 管理端服务 → 经营看板界面：返回 ADMIN_QUERY_RESP
       { success: false, error: "数据查询失败" }
     - 经营看板界面 → 管理员：核心指标区域显示"数据加载失败，
       请点击刷新重试"，其他区域正常加载
  end

  5. （后续自动触发 UML-036 营收趋势查询和 UML-037 充电桩状态统计查询）

■ 输出
  - 成功：页面顶部显示四个数字卡片，展示平台核心经营指标
  - 失败：核心指标区域显示错误提示，不影响后续子任务执行

■ 关联
  - 前序：UML-034（管理员登录）
  - 后续：UML-036（营收趋势，页面加载时自动触发）、UML-037（充电桩状态统计）
  - 数据：读取 orders 表（聚合查询）、users 表（计数查询），不修改数据
  - 业务规则：
    - 累计充电量和累计营收只统计 status='settled' 的订单
    - 累计充电次数统计所有订单（含已取消的，反映总使用频次）
    - 注册用户数统计所有状态的用户（含冻结的）


------------------------------------------------------------
【UML-036】营收趋势
------------------------------------------------------------

■ 场景
  核心指标加载完成后（或在加载核心指标的同时），经营看板页面
  中间区域展示近7日的营收趋势折线图。横轴为日期（近7天），
  纵轴为当日营收金额。管理员通过折线图直观观察营收的变化趋势
  和波动情况。

■ 参与者
  - 管理员（actor）
  - 经营看板界面
  - 管理端服务
  - 订单表（orders）

■ 前置条件
  - UML-034 管理员登录已完成
  - 经营看板界面已渲染

■ 处理流程
  1. 经营看板界面 → 经营看板界面：核心指标加载完成后（或并行触发），
     自动发起营收趋势查询
  2. 经营看板界面 → 管理端服务：发送 ADMIN_QUERY_REQ
     { type: "revenue_trend", params: { days: 7 }, session_id }
  3. 管理端服务 → 管理端服务：校验 session_id 有效性
  4. alt session_id 有效
     - 管理端服务 → 订单表：执行按日聚合查询
       SELECT
         DATE(end_time) AS date,
         SUM(total_fee) AS daily_revenue
       FROM orders
       WHERE status = 'settled'
         AND end_time >= date('now', '-6 days')
       GROUP BY DATE(end_time)
       ORDER BY date ASC
     - 管理端服务 → 管理端服务：补全无数据的日期（营收为0），
       确保返回连续7天的数据
     - 管理端服务 → 经营看板界面：返回 ADMIN_QUERY_RESP
       { type: "revenue_trend",
         data: [ { date: "2026-08-28", revenue: 234.50 },
                 { date: "2026-08-29", revenue: 312.00 },
                 ...（共7天） ] }
     - 经营看板界面 → 经营看板界面：使用折线图渲染营收趋势：
       - 横轴：日期（近7天）
       - 纵轴：营收金额（元）
       - 数据点连线显示趋势
     - 经营看板界面 → 管理员：折线图渲染完成，显示在页面中间区域
   else session_id 无效
     - （处理同 UML-035，跳转登录页）
   else 查询异常
     - 经营看板界面 → 管理员：折线图区域显示"趋势数据加载失败"
  end

■ 输出
  - 成功：页面中间区域显示近7日营收趋势折线图
  - 失败：折线图区域显示错误提示

■ 关联
  - 前序：UML-034（管理员登录）、UML-035（核心经营指标，可并行触发）
  - 后续：UML-037（充电桩状态统计，可并行触发）
  - 数据：读取 orders 表（按日聚合查询），不修改数据
  - 业务规则：
    - 只统计 status='settled' 的订单营收
    - 按 end_time 日期分组（充电结束日期）
    - 无数据的日期补0，确保折线图连续


------------------------------------------------------------
【UML-037】充电桩状态统计
------------------------------------------------------------

■ 场景
  营收趋势加载完成后（或并行触发），经营看板页面底部区域展示
  全量充电桩按状态分类的统计图表（饼图或柱状图）。管理员通过
  此图表了解当前所有充电桩的运行状态分布：空闲、使用中、已预约、
  故障各占多少。

■ 参与者
  - 管理员（actor）
  - 经营看板界面
  - 管理端服务
  - 充电桩表（charging_piles）

■ 前置条件
  - UML-034 管理员登录已完成
  - 经营看板界面已渲染

■ 处理流程
  1. 经营看板界面 → 经营看板界面：营收趋势加载完成后（或并行触发），
     自动发起充电桩状态统计查询
  2. 经营看板界面 → 管理端服务：发送 ADMIN_QUERY_REQ
     { type: "pile_status_stats", session_id }
  3. 管理端服务 → 管理端服务：校验 session_id 有效性
  4. alt session_id 有效
     - 管理端服务 → 充电桩表：执行分组统计查询
       SELECT
         status,
         COUNT(*) AS count
       FROM charging_piles
       GROUP BY status
     - 充电桩表 → 管理端服务：返回各状态的数量：
       - idle: 15
       - reserved: 3
       - in_use: 8
       - fault: 2
     - 管理端服务 → 管理端服务：组装状态分布数据，
       补全未出现的状态（数量为0）
     - 管理端服务 → 经营看板界面：返回 ADMIN_QUERY_RESP
       { type: "pile_status_stats",
         data: [ { status: "idle", label: "空闲", count: 15 },
                 { status: "reserved", label: "已预约", count: 3 },
                 { status: "in_use", label: "使用中", count: 8 },
                 { status: "fault", label: "故障", count: 2 } ] }
     - 经营看板界面 → 经营看板界面：使用饼图渲染状态分布：
       - 不同颜色表示不同状态
       - 图例显示各状态名称和数量
       - 标题：充电桩状态分布
     - 经营看板界面 → 管理员：饼图渲染完成，显示在页面底部区域
     - 经营看板界面 → 管理员：若有故障桩（count > 0），在饼图旁
       显示告警提示"当前有 N 个充电桩处于故障状态，请及时处理"，
       并附带跳转链接到充电桩管理页面（UML-038）
   else session_id 无效
     - （处理同 UML-035，跳转登录页）
   else 查询异常
     - 经营看板界面 → 管理员：饼图区域显示"状态数据加载失败"
  end

■ 输出
  - 成功：页面底部区域显示充电桩状态分布饼图，有故障桩时显示告警
  - 失败：饼图区域显示错误提示

■ 关联
  - 前序：UML-034（管理员登录）、UML-035~036（可并行触发）
  - 后续：UML-038（充电桩列表，管理员可从告警链接跳转）
  - 数据：读取 charging_piles 表（分组统计查询），不修改数据
  - 业务规则：
    - 统计全量充电桩（不区分站点）
    - 状态分类：idle(空闲) / reserved(已预约) / in_use(使用中) / fault(故障)
    - 有故障桩时显示告警，引导管理员前往充电桩管理处理


------------------------------------------------------------
  经营看板整体交互说明
------------------------------------------------------------

  管理员登录 → 看板首页加载 → 并行触发三个查询：
  ├─ UML-035 核心经营指标 → 顶部数字卡片区
  ├─ UML-036 营收趋势 → 中间折线图区
  └─ UML-037 充电桩状态统计 → 底部饼图区

  三个查询相互独立，某个失败不影响其他。管理员可点击页面右上角
  "刷新"按钮同时重新触发三个查询。看板页面是管理端首页，
  管理员可通过左侧导航栏切换到其他管理页面（桩管理、站管理、
  用户管理、订单管理）。
