================================================================================
  PC运营管理端 / 充电桩管理（UML-038 ~ UML-039，对应 B=38~39）
================================================================================

  中任务概述：
  管理员从经营看板左侧导航栏进入"充电桩管理"页面。此模块提供
  全量充电桩的列表浏览和远程操作功能：
    1）充电桩列表（UML-038）：展示所有充电桩的基本信息（编号、
       所属站点、类型、功率、状态、累计充电次数），支持按站点
       筛选和按状态筛选
    2）远程重启（UML-039）：管理员对故障桩执行远程重启操作，
       将其状态从 fault 恢复为 idle

  组件清单（本中任务涉及）：
  - 管理员（actor）
  - 充电桩管理界面（管理端列表页，含表格、筛选器、操作按钮）
  - 管理端服务（服务端，处理充电桩查询和管理操作请求）
  - 充电桩表（charging_piles）
  - 充电站表（charging_stations）
  - 管理端全局状态（提供 admin_id 和 session_id）

  解耦设计：
  - 充电桩管理是"读+操作"模块，列表查询只读不修改数据
  - 远程重启操作通过 ADMIN_ACTION_REQ 消息发送，与列表查询
    使用不同的消息类型，查询和操作分离
  - 远程重启只修改 charging_piles 表的 status 字段，不涉及订单
    和用户数据——桩状态变更与业务订单解耦
  - 与用户端充电流程（UML-025~032）的关系：用户端看到的是桩的
    当前状态，管理端的远程重启会影响用户端看到的桩状态（如故障桩
    重启后变为空闲，用户端可搜索到）


------------------------------------------------------------
【UML-038】充电桩列表
------------------------------------------------------------

■ 场景
  管理员从经营看板或左侧导航栏进入"充电桩管理"页面。页面加载后
  展示全量充电桩的列表，以表格形式呈现。每行显示一个充电桩的
  编号、所属站点名称、类型（快充/慢充）、功率、当前状态、累计
  充电次数。表格上方提供两个筛选器：站点筛选（下拉选择站点或
  "全部"）和状态筛选（下拉选择状态或"全部"）。管理员可组合
  使用筛选器缩小查看范围。

■ 参与者
  - 管理员（actor）
  - 充电桩管理界面
  - 管理端服务
  - 充电桩表（charging_piles）
  - 充电站表（charging_stations）

■ 前置条件
  - UML-034 管理员登录已完成，管理端全局状态保存了 admin_id 和 session_id

■ 处理流程
  1. 管理员 → 充电桩管理界面：点击左侧导航栏"充电桩管理"菜单
  2. 充电桩管理界面 → 充电桩管理界面：渲染页面框架，显示筛选器
     （站点下拉框默认"全部"，状态下拉框默认"全部"），表格区域
     显示"加载中..."
  3. 充电桩管理界面 → 管理端服务：发送 ADMIN_QUERY_REQ
     { type: "pile_list", params: { station_id: null, status: null },
       session_id }
  4. 管理端服务 → 管理端服务：校验 session_id 有效性
  5. alt session_id 有效
     - 管理端服务 → 充电桩表：联合充电站表查询全量充电桩
       SELECT
         p.pile_id, p.pile_number, p.pile_type, p.power_kw,
         p.status, p.total_charge_count, p.total_charge_duration,
         s.station_name
       FROM charging_piles p
       LEFT JOIN charging_stations s ON p.station_id = s.station_id
       ORDER BY s.station_name ASC, p.pile_number ASC
     - 充电桩表 → 管理端服务：返回全量充电桩记录列表
     - 管理端服务 → 充电桩管理界面：返回 ADMIN_QUERY_RESP
       { type: "pile_list",
         data: [ { pile_id, pile_number, station_name, pile_type,
                   power_kw, status, total_charge_count,
                   total_charge_duration }, ... ] }
     - 充电桩管理界面 → 充电桩管理界面：渲染表格：
       - 列1：桩编号（pile_number）
       - 列2：所属站点（station_name）
       - 列3：类型（pile_type，fast→快充，slow→慢充）
       - 列4：功率（power_kw，单位kW）
       - 列5：状态（status，idle→空闲/绿色，reserved→已预约/黄色，
         in_use→使用中/蓝色，fault→故障/红色）
       - 列6：累计充电次数（total_charge_count）
       - 列7：操作列（故障桩显示"远程重启"按钮，其他状态无操作按钮）
     - 充电桩管理界面 → 管理员：表格渲染完成

     6. （管理员可执行筛选操作）
     7. alt 管理员使用站点筛选器
        - 管理员 → 充电桩管理界面：在下拉框选择某个站点（如"东软园区站"）
        - 充电桩管理界面 → 管理端服务：发送 ADMIN_QUERY_REQ
          { type: "pile_list", params: { station_id: 3, status: null },
            session_id }
        - 管理端服务 → 充电桩表：WHERE p.station_id = 3 的联合查询
        - （返回筛选后的列表，重新渲染表格）
      else 管理员使用状态筛选器
        - 管理员 → 充电桩管理界面：在下拉框选择某个状态（如"故障"）
        - 充电桩管理界面 → 管理端服务：发送 ADMIN_QUERY_REQ
          { type: "pile_list", params: { station_id: null, status: "fault" },
            session_id }
        - 管理端服务 → 充电桩表：WHERE p.status = 'fault' 的查询
        - （返回筛选后的列表，重新渲染表格）
      else 管理员组合使用两个筛选器
        - 管理员 → 充电桩管理界面：同时选择站点和状态
        - 充电桩管理界面 → 管理端服务：发送带两个筛选条件的查询
        - （返回同时满足两个条件的列表）
      end
   else session_id 无效
     - （处理同 UML-035，跳转登录页）
  end

■ 输出
  - 成功：表格展示全量（或筛选后的）充电桩列表，故障桩行有"远程重启"按钮
  - 筛选：表格按筛选条件刷新数据
  - 失败：表格区域显示"数据加载失败，请重试"

■ 关联
  - 前序：UML-034（管理员登录）
  - 后续：UML-039（远程重启，从故障桩行的"远程重启"按钮触发）
  - 数据：读取 charging_piles 表和 charging_stations 表（联合查询），不修改数据
  - 业务规则：
    - 默认按站点名升序、桩编号升序排列
    - 只有 fault 状态的桩显示"远程重启"按钮
    - 筛选器可组合使用，每次筛选重新查询数据库


------------------------------------------------------------
【UML-039】远程重启
------------------------------------------------------------

■ 场景
  管理员在充电桩列表（UML-038）中发现状态为"故障"的充电桩，
  点击该行的"远程重启"按钮。系统向服务端发送远程重启请求，
  服务端将该桩状态从 fault 修改为 idle，模拟硬件重启恢复的过程。
  重启成功后，该桩重新出现在用户端的可用充电桩列表中。

■ 参与者
  - 管理员（actor）
  - 充电桩管理界面
  - 管理端服务
  - 充电桩表（charging_piles）

■ 前置条件
  - UML-034 管理员登录已完成
  - UML-038 充电桩列表已加载，目标桩状态为 fault

■ 处理流程
  1. 管理员 → 充电桩管理界面：点击故障桩行的"远程重启"按钮
  2. 充电桩管理界面 → 管理员：弹出确认对话框"确认远程重启
     充电桩 [桩编号]？重启后该桩将恢复为空闲状态"
  3. alt 管理员点击"确认"
     - 充电桩管理界面 → 充电桩管理界面：禁用"远程重启"按钮，
       显示"重启中..."
     - 充电桩管理界面 → 管理端服务：发送 ADMIN_ACTION_REQ
       { type: "restart_pile", params: { pile_id: 目标桩ID },
         session_id }
     - 管理端服务 → 管理端服务：校验 session_id 有效性
     - alt session_id 有效
       - 管理端服务 → 充电桩表：查询目标桩当前状态
         SELECT status FROM charging_piles WHERE pile_id = ?
       - alt 目标桩状态为 fault
         - 管理端服务 → 充电桩表：更新状态
           UPDATE charging_piles SET status = 'idle'
           WHERE pile_id = ? AND status = 'fault'
         - 充电桩表 → 管理端服务：返回受影响行数 = 1（更新成功）
         - 管理端服务 → 管理端服务：记录操作日志
           （管理员ID、操作类型、桩ID、操作时间）
         - 管理端服务 → 充电桩管理界面：返回 ADMIN_ACTION_RESP
           { success: true, message: "充电桩已重启成功" }
         - 充电桩管理界面 → 充电桩管理界面：刷新当前列表
           （重新发送 UML-038 的查询请求），该桩状态从"故障/红色"
           变为"空闲/绿色"，"远程重启"按钮消失
         - 充电桩管理界面 → 管理员：弹出提示"充电桩 [桩编号] 重启成功，
           已恢复为空闲状态"
       else 目标桩状态不是 fault（可能已被其他管理员重启或状态已变）
         - 管理端服务 → 管理端服务：检测到状态不是 fault，拒绝重启
         - 管理端服务 → 充电桩管理界面：返回 ADMIN_ACTION_RESP
           { success: false, error: "该充电桩当前状态无需重启" }
         - 充电桩管理界面 → 管理员：弹窗提示"该充电桩当前状态无需重启"
         - 充电桩管理界面 → 充电桩管理界面：刷新列表，显示最新状态
       end
     else session_id 无效
       - （处理同 UML-035，跳转登录页）
     end
   else 管理员点击"取消"
     - 充电桩管理界面 → 充电桩管理界面：关闭确认对话框，不执行任何操作
  end

■ 输出
  - 成功：目标桩状态从 fault 变为 idle，列表刷新，用户端可搜索到该桩
  - 状态不符：提示"当前状态无需重启"，列表刷新
  - 取消：不执行任何操作

■ 关联
  - 前序：UML-038（充电桩列表，从列表中的按钮触发）
  - 后续：无直接后续（列表自动刷新）
  - 数据：读取并修改 charging_piles 表（SELECT + UPDATE）
  - 业务规则：
    - 只有 fault 状态的桩可执行远程重启
    - 重启操作将 status 从 fault 改为 idle
    - 重启前需管理员确认，防止误操作
    - 远程重启模拟硬件恢复过程（实际项目中需通过设备通信协议
      发送重启指令，本项目简化为数据库状态变更）
  - 跨系统影响：
    - 重启后，用户端充电站查询（UML-018~022）可搜索到该桩为"空闲"
    - 重启后，经营看板（UML-037）的故障桩数量减少
    - 状态变更遵循充电桩状态机：fault → idle（仅通过远程重启）


------------------------------------------------------------
  充电桩管理与充电桩状态机的关系
------------------------------------------------------------

  充电桩状态机回顾（见系统架构概述）：
    idle(空闲) ──被预约──→ reserved(已预约) ──开始充电──→ in_use(使用中)
        ↑                      │                            │
        │ 取消预约              │                            │ 结束充电
        └──────────────────────┘                            │
        ↑                                                   │
        └───────────────────────────────────────────────────┘
                                                 fault(故障) ──远程重启──→ idle

  本模块涉及的桩状态变更：
  - UML-039 远程重启：fault → idle（管理员操作）

  不涉及的状态变更（由用户端充电流程触发）：
  - 被预约：idle → reserved（用户预约，UML-025）
  - 开始充电：reserved → in_use（用户开始充电，UML-027）
  - 结束充电：in_use → idle（充电结束，UML-030）
  - 取消预约：reserved → idle（用户取消，UML-026）

  本模块的管理员只关注 fault → idle 的恢复操作，其他状态变更
  由用户端充电流程自动驱动，管理端不干预。
