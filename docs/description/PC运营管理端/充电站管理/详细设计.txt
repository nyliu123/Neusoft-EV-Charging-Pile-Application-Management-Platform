================================================================================
  PC运营管理端 / 充电站管理（UML-040 ~ UML-042，对应 B=40~42）
================================================================================

  中任务概述：
  管理员从左侧导航栏进入"充电站管理"页面。此模块提供充电站的
  列表浏览、站内设备详情查看和新增充电站功能：
    1）充电站列表（UML-040）：展示所有充电站的基本信息（站名、
       地址、经纬度、单价、桩数量），支持点击进入站内设备详情
    2）站内设备详情（UML-041）：展示某个充电站下所有充电桩的
       详细信息，与充电桩管理列表类似但限定在单站范围
    3）新增充电站（UML-042）：管理员录入新充电站信息（站名、
       地址、经纬度、单价），系统自动通过地址调用腾讯地图API
       获取经纬度（或管理员手动填写），写入数据库

  组件清单（本中任务涉及）：
  - 管理员（actor）
  - 充电站管理界面（列表页，含表格、新增按钮）
  - 站内设备详情界面（单站充电桩列表页）
  - 新增充电站界面（表单页，含站名、地址、单价输入框和地图选点）
  - 管理端服务
  - 充电站表（charging_stations）
  - 充电桩表（charging_piles）
  - 腾讯地图API（地址转经纬度，复用用户端地理编码能力）
  - 管理端全局状态（提供 admin_id 和 session_id）

  解耦设计：
  - 充电站管理是"读+写"模块，列表和详情只读，新增充电站写入数据
  - 新增充电站只操作 charging_stations 表，不直接创建充电桩——
    充电桩需通过其他方式（数据库直接录入或后续扩展功能）关联到站点
  - 地理编码复用用户端的 GEOCODE_REQ/GEOCODE_RESP 消息，
    管理端服务调用同一腾讯地图API接口
  - 站内设备详情复用充电桩管理（UML-038）的查询逻辑，但限定
    station_id 参数，展示同一站点下的充电桩


------------------------------------------------------------
【UML-040】充电站列表
------------------------------------------------------------

■ 场景
  管理员从左侧导航栏进入"充电站管理"页面。页面加载后展示
  全量充电站的列表，以表格形式呈现。每行显示一个充电站的
  站名、地址、经纬度、充电单价、充电桩数量。管理员可点击
  某行进入该站的站内设备详情（UML-041），也可点击右上角
  "新增充电站"按钮进入新增流程（UML-042）。

■ 参与者
  - 管理员（actor）
  - 充电站管理界面
  - 管理端服务
  - 充电站表（charging_stations）
  - 充电桩表（charging_piles）

■ 前置条件
  - UML-034 管理员登录已完成，管理端全局状态保存了 admin_id 和 session_id

■ 处理流程
  1. 管理员 → 充电站管理界面：点击左侧导航栏"充电站管理"菜单
  2. 充电站管理界面 → 充电站管理界面：渲染页面框架，表格区域
     显示"加载中..."，右上角显示"新增充电站"按钮
  3. 充电站管理界面 → 管理端服务：发送 ADMIN_QUERY_REQ
     { type: "station_list", session_id }
  4. 管理端服务 → 管理端服务：校验 session_id 有效性
  5. alt session_id 有效
     - 管理端服务 → 充电站表：查询全量充电站，联合充电桩表统计各站桩数量
       SELECT
         s.station_id, s.station_name, s.address,
         s.longitude, s.latitude, s.price_per_kwh,
         COUNT(p.pile_id) AS pile_count
       FROM charging_stations s
       LEFT JOIN charging_piles p ON s.station_id = p.station_id
       GROUP BY s.station_id
       ORDER BY s.station_id ASC
     - 充电站表 → 管理端服务：返回全量充电站记录列表
     - 管理端服务 → 充电站管理界面：返回 ADMIN_QUERY_RESP
       { type: "station_list",
         data: [ { station_id, station_name, address,
                   longitude, latitude, price_per_kwh,
                   pile_count }, ... ] }
     - 充电站管理界面 → 充电站管理界面：渲染表格：
       - 列1：站名（station_name）
       - 列2：地址（address）
       - 列3：经纬度（longitude, latitude，格式化为6位小数）
       - 列4：充电单价（price_per_kwh，格式 ¥X.XX/度）
       - 列5：充电桩数量（pile_count）
       - 列6：操作列（"查看详情"按钮）
     - 充电站管理界面 → 管理员：表格渲染完成
   else session_id 无效
     - （处理同 UML-035，跳转登录页）
   else 查询异常
     - 充电站管理界面 → 管理员：表格区域显示"数据加载失败，请重试"
  end

  6. （管理员可点击某行"查看详情"进入 UML-041，或点击"新增充电站"
     进入 UML-042）

■ 输出
  - 成功：表格展示全量充电站列表，每行可点击进入详情
  - 失败：表格区域显示错误提示

■ 关联
  - 前序：UML-034（管理员登录）
  - 后续：UML-041（站内设备详情，点击"查看详情"触发）、
    UML-042（新增充电站，点击"新增充电站"按钮触发）
  - 数据：读取 charging_stations 表和 charging_piles 表（联合聚合查询），
    不修改数据
  - 业务规则：
    - 按 station_id 升序排列
    - 充电桩数量为该站下所有充电桩的总数（不区分状态）


------------------------------------------------------------
【UML-041】站内设备详情
------------------------------------------------------------

■ 场景
  管理员在充电站列表（UML-040）中点击某个充电站的"查看详情"
  按钮，进入该站的站内设备详情页面。页面顶部显示充电站基本信息
  （站名、地址、经纬度、单价、桩总数），下方以表格展示该站下
  所有充电桩的详细信息（编号、类型、功率、状态、累计充电次数、
  累计充电时长）。此页面与充电桩管理列表（UML-038）类似，但
  限定在单个站点范围内，展示更多桩维度信息。

■ 参与者
  - 管理员（actor）
  - 站内设备详情界面
  - 管理端服务
  - 充电桩表（charging_piles）
  - 充电站表（charging_stations）

■ 前置条件
  - UML-034 管理员登录已完成
  - UML-040 充电站列表已加载，管理员已点击某站"查看详情"

■ 处理流程
  1. 管理员 → 充电站管理界面：点击某充电站行的"查看详情"按钮
  2. 充电站管理界面 → 站内设备详情界面：传递 station_id 参数，
     切换到站内设备详情页面
  3. 站内设备详情界面 → 站内设备详情界面：渲染页面框架，
     顶部信息区和设备表格区均显示"加载中..."
  4. 站内设备详情界面 → 管理端服务：发送两个并行查询：
     a）站点基本信息查询：
        ADMIN_QUERY_REQ { type: "station_detail",
          params: { station_id: 目标站点ID }, session_id }
     b）站内充电桩列表查询：
        ADMIN_QUERY_REQ { type: "pile_list",
          params: { station_id: 目标站点ID, status: null },
          session_id }
  5. 管理端服务 → 管理端服务：校验 session_id 有效性
  6. alt session_id 有效
     - 管理端服务 → 充电站表：查询站点信息
       SELECT station_id, station_name, address, longitude,
              latitude, price_per_kwh
       FROM charging_stations WHERE station_id = ?
     - 管理端服务 → 充电桩表：查询该站下所有充电桩
       SELECT pile_id, pile_number, pile_type, power_kw,
              status, total_charge_count, total_charge_duration
       FROM charging_piles WHERE station_id = ?
       ORDER BY pile_number ASC
     - 充电站表 → 管理端服务：返回站点基本信息
     - 充电桩表 → 管理端服务：返回该站下充电桩列表
     - 管理端服务 → 站内设备详情界面：返回 ADMIN_QUERY_RESP
       （两条响应）：
       { type: "station_detail",
         data: { station_id, station_name, address, longitude,
                 latitude, price_per_kwh } }
       { type: "pile_list",
         data: [ { pile_id, pile_number, pile_type, power_kw,
                   status, total_charge_count,
                   total_charge_duration }, ... ] }
     - 站内设备详情界面 → 站内设备详情界面：渲染页面：
       - 顶部信息区：
         - 站名：[station_name]
         - 地址：[address]
         - 经纬度：[longitude, latitude]
         - 充电单价：¥[price_per_kwh]/度
         - 充电桩总数：[pile_count] 台
       - 下方设备表格：
         - 列1：桩编号（pile_number）
         - 列2：类型（pile_type，fast→快充，slow→慢充）
         - 列3：功率（power_kw，单位kW）
         - 列4：状态（同 UML-038 的颜色标注）
         - 列5：累计充电次数（total_charge_count）
         - 列6：累计充电时长（total_charge_duration，单位小时，
           格式化为 X.XX h）
         - 列7：操作列（故障桩显示"远程重启"按钮，复用 UML-039）
     - 站内设备详情界面 → 管理员：页面渲染完成
   else session_id 无效
     - （处理同 UML-035，跳转登录页）
   else 查询异常
     - 站内设备详情界面 → 管理员：显示"数据加载失败，请重试"
  end

  7. （故障桩的"远程重启"按钮复用 UML-039 的处理流程）

■ 输出
  - 成功：页面顶部显示站点信息，下方表格展示该站下所有充电桩
  - 失败：显示错误提示

■ 关联
  - 前序：UML-040（充电站列表，点击"查看详情"触发）
  - 后续：UML-039（远程重启，从故障桩行触发，复用同一逻辑）
  - 数据：读取 charging_stations 表和 charging_piles 表，不修改数据
  - 业务规则：
    - 充电桩按 pile_number 升序排列
    - 展示累计充电时长（total_charge_duration），这是 UML-038
      充电桩列表中不展示的额外维度
    - 远程重启操作复用 UML-039 的 ADMIN_ACTION_REQ 逻辑


------------------------------------------------------------
【UML-042】新增充电站
------------------------------------------------------------

■ 场景
  管理员在充电站列表（UML-040）页面点击右上角"新增充电站"按钮，
  进入新增充电站表单页面。管理员填写站名、地址、充电单价，系统
  通过地址自动调用腾讯地图API获取经纬度（也支持管理员手动修改
  经纬度）。提交后系统将新充电站写入数据库，返回充电站列表页面。

■ 参与者
  - 管理员（actor）
  - 新增充电站界面（表单页）
  - 管理端服务
  - 充电站表（charging_stations）
  - 腾讯地图API（地址转经纬度）

■ 前置条件
  - UML-034 管理员登录已完成
  - UML-040 充电站列表已加载

■ 处理流程
  1. 管理员 → 充电站管理界面：点击"新增充电站"按钮
  2. 充电站管理界面 → 新增充电站界面：切换到新增表单页面
  3. 新增充电站界面 → 新增充电站界面：渲染表单：
     - 站名输入框（必填）
     - 地址输入框（必填，输入后可点击"获取经纬度"按钮）
     - 经度输入框（只读，由地理编码自动填充，或手动解锁后编辑）
     - 纬度输入框（只读，由地理编码自动填充，或手动解锁后编辑）
     - 充电单价输入框（必填，单位元/度，支持小数点后两位）
     - "提交"按钮、("取消"按钮

  4. 管理员 → 新增充电站界面：填写站名和地址，点击"获取经纬度"
  5. 新增充电站界面 → 管理端服务：发送 GEOCODE_REQ
     { address: "输入的地址文本" }
  6. 管理端服务 → 腾讯地图API：调用地址转经纬度接口
  7. alt 地理编码成功
     - 腾讯地图API → 管理端服务：返回 { lng, lat }
     - 管理端服务 → 新增充电站界面：返回 GEOCODE_RESP
       { lng: 116.397428, lat: 39.90923 }
     - 新增充电站界面 → 新增充电站界面：将经纬度填入只读输入框
     - 新增充电站界面 → 管理员：经纬度框显示获取到的坐标
   else 地理编码失败（地址无法解析）
     - 管理端服务 → 新增充电站界面：返回 GEOCODE_RESP
       { error: "地址无法解析，请检查地址或手动填写经纬度" }
     - 新增充电站界面 → 管理员：提示"地址无法解析，请手动填写经纬度"
     - 新增充电站界面 → 新增充电站界面：解锁经纬度输入框为可编辑，
       允许管理员手动输入
  end

  8. 管理员 → 新增充电站界面：填写充电单价，点击"提交"按钮
  9. 新增充电站界面 → 新增充电站界面：前端校验：
     - 站名非空，长度1~100字符
     - 地址非空
     - 经纬度已填写（非空且为合法数值）
     - 充电单价 > 0，为合法正数
  10. alt 前端校验通过
      - 新增充电站界面 → 管理端服务：发送 ADMIN_ACTION_REQ
        { type: "add_station",
          params: { station_name, address, longitude, latitude,
                    price_per_kwh },
          session_id }
      - 管理端服务 → 管理端服务：校验 session_id 有效性
      - alt session_id 有效
        - 管理端服务 → 充电站表：INSERT 新充电站记录
          INSERT INTO charging_stations
            (station_name, address, longitude, latitude, price_per_kwh)
          VALUES (?, ?, ?, ?, ?)
        - alt 插入成功
          - 充电站表 → 管理端服务：返回新插入的 station_id
          - 管理端服务 → 管理端服务：记录操作日志
            （管理员ID、操作类型=add_station、站点ID、操作时间）
          - 管理端服务 → 新增充电站界面：返回 ADMIN_ACTION_RESP
            { success: true, station_id: 新ID,
              message: "充电站创建成功" }
          - 新增充电站界面 → 充电站管理界面：返回充电站列表页面，
            自动刷新列表（新站出现在列表末尾）
          - 新增充电站界面 → 管理员：弹出提示"充电站 [站名] 创建成功"
        else 插入失败（如站名重复等约束冲突）
          - 充电站表 → 管理端服务：返回数据库错误
          - 管理端服务 → 新增充电站界面：返回 ADMIN_ACTION_RESP
            { success: false, error: "创建失败：站名可能已存在" }
          - 新增充电站界面 → 管理员：弹窗提示错误原因，停留表单页
      else session_id 无效
        - （处理同 UML-035，跳转登录页）
      end
    else 前端校验失败
      - 新增充电站界面 → 管理员：对应字段下方显示红色错误提示：
        - 站名为空："请输入充电站名称"
        - 地址为空："请输入充电站地址"
        - 经纬度为空："请获取或填写经纬度"
        - 单价不合法："请输入合法的充电单价（大于0的数字）"
  end

  11. alt 管理员点击"取消"
      - 新增充电站界面 → 充电站管理界面：返回充电站列表页面，
        不保存任何输入

■ 输出
  - 成功：新充电站写入数据库，返回列表页，新站出现在列表中
  - 地理编码失败：解锁经纬度手动输入，管理员可继续填写
  - 校验失败：对应字段显示错误提示
  - 取消：返回列表页，不保存

■ 关联
  - 前序：UML-040（充电站列表，点击"新增充电站"触发）
  - 后续：UML-040（返回列表页自动刷新）、UML-041（可查看新站的
    站内设备详情——但新站下尚无充电桩，需后续通过数据库或其他
    方式添加充电桩关联到该站）
  - 数据：写入 charging_stations 表（INSERT），不修改充电桩表
  - 业务规则：
    - 新增充电站只创建站点记录，不自动创建充电桩
    - 充电桩与站点的关联需通过其他方式（数据库直接录入或后续扩展）
    - 地理编码复用用户端的腾讯地图API调用（GEOCODE_REQ/GEOCODE_RESP）
    - 站名不要求唯一约束，但建议不重复
  - 跨系统影响：
    - 新增充电站后，用户端充电站查询（UML-018~022）可搜索到该站
    - 新增充电站出现在经营看板的数据中（如有桩则计入桩总数）


------------------------------------------------------------
  充电站管理与充电桩管理的关系
------------------------------------------------------------

  充电站管理和充电桩管理是两个密切相关的模块：

  - 充电站是组织单位，充电桩从属于充电站
  - 充电站列表（UML-040）展示"站"维度信息 + 桩数量汇总
  - 站内设备详情（UML-041）展示某站下"桩"维度信息，与充电桩
    管理（UML-038）的列表结构一致，但额外展示累计充电时长
  - 充电桩管理（UML-038）展示全量桩（跨站），支持按站筛选
  - 远程重启（UML-039）在充电桩管理和站内设备详情中均可触发，
    复用同一 ADMIN_ACTION_REQ 逻辑

  管理端导航结构：
  经营看板（首页）
  ├─ 充电桩管理 → 全量充电桩列表（跨站）
  ├─ 充电站管理 → 充电站列表 → 站内设备详情（单站桩列表）
  ├─ 用户管理 → 用户列表 + 查询 + 冻结/解冻
  └─ 订单管理 → 订单列表 + 筛选
