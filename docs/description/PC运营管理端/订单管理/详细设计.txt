================================================================================
  PC运营管理端 / 订单管理（UML-046，对应 B=46）
================================================================================

  中任务概述：
  管理员从左侧导航栏进入"订单管理"页面。此模块提供全量充电
  订单的列表浏览和筛选功能。管理员可按订单状态、充电站、
  时间范围筛选订单，查看每条订单的详细信息（订单ID、用户、
  充电桩、充电站、状态、预约时间、开始/结束时间、充电量、
  单价、总费用）。此模块为只读查询模块，管理员不修改订单数据。

  组件清单（本中任务涉及）：
  - 管理员（actor）
  - 订单管理界面（列表页，含筛选器、表格）
  - 管理端服务
  - 订单表（orders）
  - 充电桩表（charging_piles）
  - 充电站表（charging_stations）
  - 用户表（users）
  - 管理端全局状态（提供 admin_id 和 session_id）

  解耦设计：
  - 订单管理是纯只读模块，不修改任何业务数据
  - 管理端订单管理与用户端订单查询（UML-033）的区别：
    - 用户端只查自己的订单（WHERE user_id = ?）
    - 管理端查全量订单，支持多维度筛选
  - 管理端只查看订单数据，不处理订单生命周期（预约→充电→结算
    由用户端充电流程 UML-025~032 驱动）


------------------------------------------------------------
【UML-046】订单列表与筛选
------------------------------------------------------------

■ 场景
  管理员从左侧导航栏进入"订单管理"页面。页面加载后展示全量
  充电订单的列表，以表格形式呈现。表格上方提供筛选器：
    1）订单状态下拉框（全部/预约中/充电中/待结算/已结算/已取消）
    2）充电站下拉框（全部/选择某站点）
    3）时间范围选择器（全部/今日/近7日/近30日/自定义日期范围）
  管理员可组合使用筛选器缩小查看范围。表格默认按订单创建时间
  倒序排列（最新订单在最上方）。

■ 参与者
  - 管理员（actor）
  - 订单管理界面
  - 管理端服务
  - 订单表（orders）
  - 充电站表（charging_stations）
  - 充电桩表（charging_piles）
  - 用户表（users）

■ 前置条件
  - UML-034 管理员登录已完成，管理端全局状态保存了 admin_id 和 session_id

■ 处理流程
  1. 管理员 → 订单管理界面：点击左侧导航栏"订单管理"菜单
  2. 订单管理界面 → 订单管理界面：渲染页面框架：
     - 筛选器区域（状态下拉框默认"全部"，站点下拉框默认"全部"，
       时间范围默认"全部"）
     - 表格区域显示"加载中..."
  3. 订单管理界面 → 管理端服务：发送 ADMIN_QUERY_REQ
     { type: "order_list",
       params: { status: null, station_id: null,
                 start_date: null, end_date: null },
       session_id }
  4. 管理端服务 → 管理端服务：校验 session_id 有效性
  5. alt session_id 有效
     - 管理端服务 → 订单表：联合查询全量订单
       SELECT
         o.order_id, o.status,
         o.reserve_time, o.start_time, o.end_time,
         o.charge_amount_kwh, o.price_per_kwh, o.total_fee,
         u.phone AS user_phone, u.nickname AS user_nickname,
         p.pile_number, p.pile_type,
         s.station_name
       FROM orders o
       LEFT JOIN users u ON o.user_id = u.user_id
       LEFT JOIN charging_piles p ON o.pile_id = p.pile_id
       LEFT JOIN charging_stations s ON o.station_id = s.station_id
       ORDER BY o.reserve_time DESC
     - 订单表 → 管理端服务：返回全量订单记录列表
     - 管理端服务 → 订单管理界面：返回 ADMIN_QUERY_RESP
       { type: "order_list",
         data: [ { order_id, status, reserve_time, start_time,
                   end_time, charge_amount_kwh, price_per_kwh,
                   total_fee, user_phone, user_nickname,
                   pile_number, pile_type, station_name }, ... ] }
     - 订单管理界面 → 订单管理界面：渲染表格：
       - 列1：订单ID（order_id）
       - 列2：用户（user_nickname + 脱敏手机号）
       - 列3：充电站（station_name）
       - 列4：充电桩（pile_number + 类型标识：快充/慢充）
       - 列5：订单状态（status，带颜色标注：
         reserved→预约中/黄色，charging→充电中/蓝色，
         pending_settlement→待结算/橙色，
         settled→已结算/绿色，cancelled→已取消/灰色）
       - 列6：预约时间（reserve_time，格式 YYYY-MM-DD HH:MM）
       - 列7：充电时间（start_time ~ end_time，如未结束则显示
         start_time ~ "进行中"）
       - 列8：充电量（charge_amount_kwh，单位度，未充电时显示"-"）
       - 列9：单价（price_per_kwh，格式 ¥X.XX/度）
       - 列10：总费用（total_fee，格式 ¥XX.XX，未结算时显示"-"）
     - 订单管理界面 → 管理员：表格渲染完成，表格上方显示
       "共 N 条订单记录"
   else session_id 无效
     - （处理同 UML-035，跳转登录页）
   else 查询异常
     - 订单管理界面 → 管理员：表格区域显示"数据加载失败，请重试"
  end

  6. （管理员可使用筛选器筛选订单）
  7. loop 管理员使用筛选器
     - alt 按状态筛选
       - 管理员 → 订单管理界面：在状态下拉框选择某状态（如"已结算"）
       - 订单管理界面 → 管理端服务：发送 ADMIN_QUERY_REQ
         { type: "order_list",
           params: { status: "settled", station_id: 当前值,
                     start_date: 当前值, end_date: 当前值 },
           session_id }
       - 管理端服务 → 订单表：WHERE o.status = 'settled' 的联合查询
       - （返回筛选后的列表，重新渲染表格）
     else 按充电站筛选
       - 管理员 → 订单管理界面：在站点下拉框选择某站点
       - 订单管理界面 → 管理端服务：发送带 station_id 的查询
       - 管理端服务 → 订单表：WHERE o.station_id = ? 的查询
       - （返回该站下的订单）
     else 按时间范围筛选
       - 管理员 → 订单管理界面：选择时间范围（如"近7日"或自定义）
       - 订单管理界面 → 管理端服务：发送带 start_date 和 end_date 的查询
       - 管理端服务 → 订单表：WHERE o.reserve_time >= start_date
         AND o.reserve_time < end_date 的查询
       - （返回时间范围内的订单）
     else 组合筛选
       - 管理员 → 订单管理界面：同时设置多个筛选条件
       - 订单管理界面 → 管理端服务：发送带所有筛选条件的查询
       - 管理端服务 → 订单表：组合 WHERE 条件的查询
       - （返回同时满足所有条件的订单）
     end
     - 管理端服务 → 订单管理界面：返回筛选后的列表
     - 订单管理界面 → 订单管理界面：重新渲染表格，
       显示"找到 N 条匹配订单"
  end

  8. alt 管理员点击"重置筛选"
     - 订单管理界面 → 订单管理界面：清空所有筛选器为默认值
     - 订单管理界面 → 管理端服务：发送无筛选条件的查询
     - （恢复全量列表）
  end

■ 输出
  - 成功：表格展示全量（或筛选后的）订单列表，按预约时间倒序
  - 筛选：表格按筛选条件刷新数据，显示匹配数量
  - 重置：恢复全量列表
  - 失败：表格区域显示错误提示

■ 关联
  - 前序：UML-034（管理员登录）
  - 后续：无直接后续（只读查看，不触发其他操作）
  - 数据：读取 orders 表（联合 users、charging_piles、
    charging_stations 多表查询），不修改数据
  - 业务规则：
    - 默认按预约时间倒序排列（最新订单在最上方）
    - 筛选器可组合使用，每次筛选重新查询数据库
    - 订单状态颜色标注：
      reserved(预约中)/黄色、charging(充电中)/蓝色、
      pending_settlement(待结算)/橙色、
      settled(已结算)/绿色、cancelled(已取消)/灰色
    - 充电量和总费用在未结算时显示"-"，结算后显示具体数值
    - 管理端只查看订单，不修改订单状态（订单状态由用户端
      充电流程 UML-025~032 自然驱动）
  - 与用户端订单查询的区别：
    - 用户端（UML-033）：只查自己的订单，按时间倒序，无筛选
    - 管理端（UML-046）：查全量订单，支持状态/站点/时间组合筛选，
      展示用户信息、充电桩信息等多维度数据
  - 管理端订单管理不提供订单的增删改操作——订单是业务流转
    的自然产物，管理端只监控不干预

  管理端6个中任务的完整流转：

  1. UML-034 管理员登录 → 验证通过 → 进入经营看板
  2. UML-035 核心经营指标 } 三个查询并行触发，
  3. UML-036 营收趋势     } 某个失败不影响其他,
  4. UML-037 充电桩状态统计 } 故障桩有告警链接→充电桩管理
  5. UML-038 充电桩列表 → 全量桩列表，故障桩有"远程重启"按钮
  6. UML-039 远程重启 → fault → idle，刷新列表
  7. UML-040 充电站列表 → 全量站列表，每站可"查看详情"
  8. UML-041 站内设备详情 → 单站桩列表，复用远程重启
  9. UML-042 新增充电站 → 表单填写→地理编码→写入数据库
  10. UML-043 用户列表 → 全量用户列表，各用户有"冻结/解冻"按钮
  11. UML-044 手机号模糊查询 → 搜索框输入片段，实时模糊匹配
  12. UML-045 冻结与解冻 → normal↔frozen，影响用户端登录
  13. UML-046 订单列表与筛选 → 全量订单，支持多维度组合筛选

  管理端对用户端的影响：
  - 冻结用户 → 用户端登录被拦截（UML-011）
  - 远程重启故障桩 → 用户端可搜索到该桩为空闲（UML-018~022）
  - 新增充电站 → 用户端充电站查询可搜索到新站
  - 这些影响是实时生效的，因为两端共享同一数据库

  管理端的核心定位：
  - 监控：经营看板展示核心指标和趋势
  - 管理：充电桩状态恢复、充电站新增、用户状态管理
  - 查询：充电桩列表、充电站列表+详情、用户列表+查询、订单列表+筛选
  - 管理端不直接干预订单流转（预约→充电→结算由用户端驱动）
